# Agent Office 문서 지도

처음 이어받는 사람은 **제품 맥락 → 골든 정책 → 세션 분석 → 공통 규격 → 코드** 순서로 읽는다. 이 문서들은 공급자 하나의 구현을 제품 전체의 정책으로 확대하지 않기 위한 기준이다.

| 문서 | 답하는 질문 | 역할 |
| --- | --- | --- |
| [프로젝트 맥락과 의사결정](PROJECT-CONTEXT.md) | 왜 이 사무실을 만들었고 어떤 방향이 채택되었나? | 사용자 요구, 바뀐 결정, 후속 작업 경계 |
| [골든 사무실 정책](GOLDEN-OFFICE-POLICY.md) | 무엇을 어떻게 보여야 하나? | 그룹, 가구, 상태, 대화, 소식의 제품 정본 |
| [세션 기록 분석과 수집 모듈](SESSION-INGESTION.md) | 기록을 어떻게 읽고 같은 세션임을 판단하나? | 처리 흐름, 자체/외부 구현 경계, 장애 분석 |

| [테마 시안](design/office-themes-2026-10-04.md) | 어떤 시각 방향을 비교했나? | 독립 시안 카탈로그, 제품 채택과 구분 |

실행은 [루트 README](../README.md), 외부 코드의 법적 고지는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md), 시안 E 원본은 [references/design-source](../references/design-source/README.md)에 있다. `PLAN.md`와 `update_note.md`는 구현 계획·날짜별 이력이며 현재 제품 계약을 덮어쓰지 않는다.

새 변경은 관련 정본을 함께 고친다. 코드와 문서가 다르면 현재 코드의 실제 동작을 확인하고 불일치를 수정한다. 테스트 수, 실제 세션 수, 서비스 PID 등 변동하는 값은 골든 정책에 고정하지 않는다. 실제 세션 원문·개인 캡처·인증정보는 Git에 넣지 않는다.
