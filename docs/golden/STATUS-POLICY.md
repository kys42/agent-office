# 상태 정책서 — 동료의 상태는 어떻게 정하고 어떻게 보여 주나

[골든 문서](README.md) · [관측 규격](OFFICE-OBSERVATION-PROTOCOL.md) · [사무실 정책](GOLDEN-OFFICE-POLICY.md) · [기능 정책서](FEATURE-POLICY.md)

동료 상태를 바꾸거나 새 화면에서 상태를 쓸 때 먼저 보는 정본이다. 코드 정본은 `src/shared/runtime.ts`(`deriveState`), `src/shared/presentation.ts`, `src/shared/triage.ts`, `src/shared/office.ts`(`officeZone`)다.

## 1. 세 층

| 층 | 무엇 | 누가 |
|---|---|---|
| 관측 | 원본 기록에서 확인한 사실: 작업(work), 생각(think), 호출(call), 오류(error), 응답 완료(done) | 공급자 어댑터 (`server/adapters`) |
| 파생 | 마지막 활동 이후 흐른 시간으로 정하는 상태: 대기 중 → 쉬는 중 → 퇴근 | `deriveState` (서버 `store.decorate`가 설정값으로 다시 계산) |
| 표현 | 라벨·색·자세·할 일 그룹·공간 | 화면 공통 코어(`buildOfficeModel`) |

관측은 바꾸지 않고 보존한다(`observedStatus`). 파생과 표현은 언제든 다시 계산한다. 공급자마다 다른 시간 규칙을 넣지 않는다.

## 2. 상태 사다리

마지막 활동(원본 `updatedAt`) 기준이며 공급자 공통이다.

| 마지막 활동 후 | 상태 | 라벨 | 공간 |
|---|---|---|---|
| 0–2분 | work / think / done | 일하는 중 / 생각 중 / 응답 완료 | 사무실 |
| 2분 – 대기 시간 | **ready** | **대기 중** | 사무실 |
| 대기 시간 – 퇴근 시간 | idle | 쉬는 중 | 사무실 |
| 퇴근 시간 이후 | sleep | **퇴근** | 대기 라운지 |
| 보관 일수 이후 | (공간만 이동) | — | 보관 공간 |

- **대기 시간** `readyMinutes`: 기본 30분, 설정에서 10·20·30·60분. 서버는 5–240분을 받고, 퇴근 시간보다 짧아야 한다
- **퇴근 시간** `standbyHours`: 기본 4시간, 1시간–90일
- **보관 일수** `archiveDays`: 기본 7일, 1–365일. 끌 수 있다(`autoArchive: false`)
- 세 시점 모두 **마지막 활동부터** 센다. 순서는 항상 대기 중 → 쉬는 중 → 퇴근 → 보관이다. 순서가 어긋나는 설정은 저장하지 않는다
- 2분은 "아직 실행 중일 수 있는 조용함"의 경계다(`QUIET_MS`). 대기 중은 일하는 중으로 세지 않는다

## 3. 시간이 지나도 바뀌지 않는 것

- **호출(call)과 오류(error)**는 대기 중·쉬는 중으로 내려가지 않는다. 확인하거나 원래 앱에서 답할 때까지 '나를 기다려요'에 남는다. 다만 퇴근 시간이 지나면 다른 동료처럼 퇴근(라운지)으로 가고, 그때부터는 할 일 그룹과 펫 숫자에서 빠진다(기존 동작 유지. 미응답 호출을 계속 남길지는 후속 결정)
- **직접 보관**(`archived`)은 모든 시간 규칙보다 앞선다 → 보관됨(leave)
- **고정**(`pinned`)한 동료는 자동으로 라운지·보관으로 옮기지 않는다. 상태 라벨(대기 중·쉬는 중·퇴근)은 그대로 시간에 따른다
- **사무실로 데려오기**(`returnedAt`)는 공간 계산의 기준 시각만 당긴다. 원본 `updatedAt`은 바꾸지 않는다
- **가리기**(`hiddenAt`)는 상태를 바꾸지 않고 장면에서만 뺀다. 부르는 동료는 가려지지 않는다([기능 정책서](FEATURE-POLICY.md#가리기))

## 4. 표현 매핑

| 상태 | 라벨 | 색 | 자세(장식) | 할 일 그룹 |
|---|---|---|---|---|
| call | 불러요 | 빨강 | 손들기 | 나를 기다려요 |
| error | 확인 필요 | 주황 | 차분한 확인 표식 | 나를 기다려요 |
| work | 일하는 중 | 초록 | 타이핑 | 일하는 중 |
| think | 생각 중 | 보라 | 생각하는 모습 | 일하는 중 |
| done | 응답 완료 | 파랑 | 결과 봉투(2분) | 대기 중 |
| **ready** | **대기 중** | 하늘 | **자리에서 바르게 대기**(졸거나 산책하지 않음) | **대기 중** |
| idle | 쉬는 중 | 회색 | 기지개·자리 옆 산책·졸기(장식) | 쉬는 중 |
| sleep | **퇴근** | 짙은 회색 | 라운지 소파·침대 | (라운지) |
| leave | 보관됨 | — | 보관 | (보관) |

- **할 일 그룹 순서**: 나를 기다려요 → 확인할 결과 → 일하는 중 → **대기 중** → 쉬는 중. 미확인 중요 소식이 있으면 상태와 관계없이 '확인할 결과'가 먼저다
- 명단, 데스크 펫 요약, 책상 줄 모두 같은 그룹을 쓴다(`triageGroup`). 펫은 가장 급한 그룹과 인원 하나만 말한다
- 업무 카드의 '지금' 카드도 같은 단계를 쓴다: 대기 중이면 "대기 중 · 방금 일을 마쳤어요", 쉬는 중이면 "지금은 조용해요".
- 서버가 다시 계산하기 전의 원시 상태도 같은 규칙을 따른다. 2분이 지났지만 기본 대기 시간 안인 work·think와 막 끝난 done은 대기 중으로 보고, 그 시간이 지난 work·think는 쉬는 중으로 본다(`isStandingBy`). 원시 상태에는 기본 대기 시간(30분)을 쓴다. 실제 앱은 서버가 설정값으로 계산한 상태를 받는다
- 자세는 장식이다. 실제 프로세스 정지나 다른 행동을 주장하지 않는다. 움직임 줄이기와 배경 탭에서는 멈춘다

## 5. 추측하지 않는 것

- "프로세스가 끝났다", "작업이 성공했다"는 결론을 만들지 않는다. 응답 완료는 업무 완료가 아니다
- PID나 CLI 설치 여부로 실행 중을 꾸미지 않는다
- 조용함만으로 원본 세션의 종료를 확정하지 않는다. 대기·쉬는 중·퇴근은 표현일 뿐이다

## 6. 바꿀 때

- 시간 규칙은 `deriveState`와 `officeZone`에서만 바꾼다. 화면별·공급자별 예외를 만들지 않는다
- 새 상태를 넣으면 아래를 함께 갱신한다
  - `Mood`, `MOODS`(라벨·색), `SPRITE_ROWS`, `runtime.phases`
  - `presentSession` 자세, `triageGroup`, 펫 라벨(`PET_LABELS`), 명단 설명(`HINTS`)
  - 이 문서의 표
- 필수 검증: 사다리 경계(1분·5분·대기 시간 전후·퇴근 시간), 설정 범위와 순서 검증, 호출·오류 유지, 할 일 그룹 순서, UI 라벨. 참고 테스트는 `tests/status-policy.test.ts`
