# Agent Office 골든 정책 — 동료, 공간, 상태와 소식

정본 v6 · 2026-10-05. 사용자 요청: 여러 에이전트 플랫폼을 하나의 사무실로 읽고, 사람이 자리를 비워도 중요한 맥락을 놓치지 않게 한다. 시안 테마와 무관한 제품·구현 계약이다.

읽기 순서와 역할은 [문서 지도](../README.md), 사용자 요구·대체된 결정은 [프로젝트 맥락](PROJECT-CONTEXT.md), 실제 자체/외부 구현 경계는 [세션 기록 분석](../development/SESSION-INGESTION.md)을 따른다. 이 문서는 제품 정책의 정본이며 과거 조사 기록이나 테마 시안이 이를 덮어쓰지 않는다.

## 1. 절대 분리할 네 층

```text
Claude Code / Codex / OpenClaw / 다음 공급자
  → 공급자 어댑터: 원본 형식, 식별자, 공개 메시지, 관계 근거 해석
  → 공통 관측 규격: Session + RuntimeObservation + Relation + OfficeEvent
  → 공통 제품 정책: 프로젝트/브랜치 공간, 좌석, 소식/읽음, 대기/보관
  → 표현: 책상/표지판/캐릭터 동작/말풍선/오른쪽 상세/데스크 펫·책상 줄
```

화면에 공급자의 원본 이벤트 이름이나 로그 경로 패턴 분기를 추가하지 않는다. 새 플랫폼은 어댑터에서 같은 규격을 채우고 공통 계약 테스트를 통과해야 한다. 공급자 이름은 출처와 캐릭터 선택에만 쓰며 상태의 의미를 바꾸지 않는다. 원본의 지원 여부, 수집기의 연결 상태, 세션의 작업 상태, 장식 동작은 서로 다른 축이다.

정본 코드: `src/shared/types.ts`(필드), `src/shared/runtime.ts`(실행 관측·시간 정책), `src/shared/residents.ts`(동료 표시 투영), `src/shared/office-assets.ts`(에셋 계약), `src/shared/office.ts`(그룹·영속 순서), `src/shared/office-layout.ts`(실제 가구 배치), `src/shared/branch.ts`(브랜치 표시), `src/shared/presentation.ts`(관측→동작), `src/shared/notices.ts`(소식), `server/adapters/`(원본), `server/workspaces.ts`(공통 Git 위치), `server/store.ts`(사용자 상태/영속성).

| 대상 | 규격과 의미 | 정보가 없을 때 |
| --- | --- | --- |
| 세션 정체성 | 공급자 + 네임스페이스 + 원본 대화 ID. 실행 파일/로그 파일 ID와 다름 | 안정적인 원본 식별 근거, 파일 기반 fallback임을 유지 |
| 이름 | 사용자 별명 → 원본 표시 이름 → 정제된 실제 요청 → 역할·작업 공간 이름 | 자동 첨부 XML, 환경 설명, 도구 인수는 제목 금지 |
| 작업 위치 | 원본 cwd + 검증된 Git common-dir/project root + worktree | 경로 기준으로만 그룹, 없는 저장소를 추정하지 않음 |
| 브랜치/커밋 | 세션 기록의 branch와 gitCommit, 별도 현재 workspace.git | 기록 이름 → 기록 커밋 → 출처를 표시한 현재 branch/HEAD → 기록 없음. 현재 checkout으로 과거 기록을 덮어쓰지 않음 |
| 관계 | root / subagent / fork / child / unknown, 부모 원본 ID, 출처 | 동시 실행이나 제목 유사성으로 부모를 만들지 않음 |
| 실행 관측 | working / thinking / needs-input / responded / interrupted / error / quiet / unknown | 마지막 관측 시각과 이유를 보존 |
| 공개 이벤트 | user / assistant / tool / result / lifecycle; 안정적인 event ID와 시각 | 내부 분석·숨겨진 추론은 표시/알림에 넣지 않음 |
| 공개 설명 | 현재 턴의 진행 메시지 → 받은 요청 → 설명 미확인 | exec 같은 도구 이름으로 작업 내용을 지어내지 않음 |
| 결과물 | 원문에서 관측한 PR/이슈 URL + 별도 조회한 제목/상태 | 링크 발견을 생성·병합·성공의 근거로 승격하지 않음 |
| 사용량 | 숫자 또는 null, session/sample 범위와 출처 | 0으로 채우지 않음; 누적·문맥 한도·현재 사용량 분리 |
| 수집 신뢰 | observed/derived/unknown + 부분 수집 여부 + 원본 위치 | 미관측(null), 부분 수집, 연결 오류를 구분. 원본 미지원 여부는 공급자 계약에 기록 |

`RuntimeObservation`은 실제 원본 상태를 보존한다. 오래 조용하다고 작업 성공/프로세스 종료로 바꾸지 않는다. `Session.status`는 호환 표시 값이며 휴식/대기 표시에 사용할 수 있지만 원본 관측의 대체물이 아니다. `presentSession`은 이 규격을 읽는 공통 표현 함수다.

## 3. 여러 플랫폼에서 특히 주의할 정체성

| 소스 | 처리 규칙 |
| --- | --- |
| Codex continuation | 파일명 UUID가 바뀌어도 첫 session_meta의 대화 ID가 같으면 같은 세션. 여러 조각의 이벤트를 ID로 병합하고 최신 관측을 채택 |
| Codex 실제 서브에이전트 | source.subagent/thread_source와 부모 ID를 근거로 별도 세션 유지. 현재 작업의 결과 확인을 위해 부모 옆 보조 책상 유지, 다음 부모 요청에서 접기 |
| Codex fork | forked_from_id는 분기 관계. 서브에이전트로 축소하지 않음 |
| Claude subagents | subagents 파일의 agentId를 독립 ID로 사용. 상위 디렉터리의 원본 세션 ID와 isSidechain이 관계 근거 |
| Claude parentUuid | 대화 내 메시지 부모일 수 있음. 그 값 하나로 부모 세션을 만들지 않음 |
| OpenClaw SQLite | agent 네임스페이스 + current_session_id. parent_session_key는 key→session ID를 해석한 뒤 연결; 알 수 없는 부모는 미해결 관계 |
| 자동 첨부 컨텍스트 | in-app-browser-context, 환경/권한/AGENTS, external open-page context는 제목·사용자 요청·새 업무 효과에서 제외 |
| 상속한 이력 | 부모의 과거 대화는 서브에이전트의 새 요청/새 결과로 알리지 않음 |

같은 대화 조각을 병합할 때 사용자 메모/별명/핀은 원본 canonical ID에 남긴다. 잘못 만들어졌던 파일 ID 행은 재수집에서 사라져도 원본 로그와 사용자 메모를 삭제하지 않는다. 정상적인 독립 fork와 실제 subagent는 병합하지 않는다.

### 동료와 실행 기록의 분리

- `Session`은 원본 대화/실행 기록이다. `OfficeResident`는 사무실에 서 있는 동료의 표현이다. 표시를 합친다고 대화·메모·읽음·MCP 세션 ID를 합치지 않는다.
- OpenClaw는 **agent 디렉터리의 페르소나별 한 명**. `actor.id=openclaw:<agentName>`를 좌석 정체성으로 사용한다. 대표 실행은 확인 필요 → 최근 작업 중 → 핀 → 일반 대화 → 기타 실행 → 보관된 기록 순으로 정하고, 같은 순위에서는 최근 활동을 우선한다. 실행이 바뀌어도 페르소나의 좌석 순서 키는 유지한다.
- 대표의 프로젝트/브랜치/작업 상태를 표시한다. 동시 실행 수와 전체 실행 수를 함께 볼 수 있고 오른쪽의 ‘페르소나의 실행 기록’에서 원본 대화를 고른다. 별명·메모·보관·핀은 현재 선택한 **실행 기록**에 적용한다. 페르소나 자체 꾸미기/별명 저장은 후속 계약으로 분리한다.
- 자동 실행만 있고 작업이 끝난 페르소나는 라운지에서 쉰다. 핀·직접 복귀·확인 필요·작업 중은 사무실 표현에 우선한다. 일반 대화가 있으면 그 대화의 대기/보관 시간을 따른다.
- 일반 보조 세션은 응답이 끝나도 **부모의 현재 작업 동안 낮은 책상에 남긴다**. 부모·상위 메인에 보조 자신의 작업 시작보다 새로운 요청/명시적 turn 시작이 관측되면 이전 보조를 ‘보조·자동 작업 기록’에 접는다. 최근 작업 중·미해결 확인 필요·핀은 예외로 계속 보인다. 늦은 최종 응답이나 도구/폴링 시각만으로 다시 등장하지 않고, 보조에게 새 요청이 전달되면 다시 참여한다. 메인이 대기/보관으로 이동하면 완료한 보조도 접는다. 부모 미수집은 즉시 숨김 근거가 아니며 자기 대기 시점까지 보존한다. 독립 fork와 OpenClaw 페르소나 투영은 이 보조 자리 수명과 분리한다.
- Codex의 guardian/review/compact/memory_consolidation과 internal source는 **원본의 비사용자 origin 메타데이터**로만 내부 보조로 구분한다. 역할/제목에 guardian이 있다는 이유만으로 숨기지 않는다. 내부 보조는 작업 중이어도 일반 책상을 만들지 않고 확인 필요 또는 핀으로 드러낸다. ‘Guardian이 어떤 검토를 하는가’는 원본이 보장하지 않으므로 추측하지 않는다.
- OpenClaw cron은 `created_via=cron` 또는 구조화된 `agent:<agent>:cron:` 키를 근거로 판별한다. 조용한 cron마다 새로운 캐릭터/최종 응답 배지를 쌓지 않는다. 전체 기록·해당 실행 상세에서 원문은 계속 볼 수 있다.
- 중요 소식함의 기본 최종 응답에서는 보조/내부/예약 실행을 제외하되, 미해결 질문·오류는 유지한다. 필터는 삭제나 자동 읽음 처리가 아니다. 데스크 펫·책상 줄도 큰 사무실과 같은 `buildOfficeModel` 결과(동료 투영·할 일 그룹·소식 기준)를 그린다.

| provider / agent profile | 캐릭터, 출처 필터 | 채택. 서로 다른 플랫폼도 같은 프로젝트 구역에 가능 |
| 원본 작업/티켓 ID | 같은 목적을 하는 세션 모음 | 후보. 정확한 공통 ID가 생기면 추가; 제목 유사도만으로 묶지 않음 |
| repository URL | 다른 컴퓨터/clone의 같은 제품 | 후보. 사용자 연결과 host 구분이 준비된 뒤 |
| 모델 / 역할 / 모드 | 상세 비교, 작업 역할 표시 | 역할은 관측된 경우 상세. 모델별 책상 그룹은 후보 |
| 최근 사용 / 앱 내 열람 빈도 | 명단/검색 순서 | 채택. 물리적 좌석 위치에는 영향 없음 |
| 핀 / 수동 프로젝트 별칭 | 자주 쓰는 자리 유지, 긴 이름 보완 | 핀 채택. 팀 별칭/사용자 지정 구역은 후보 |
| 경로의 공통 접두사 | 폴더 군집 | 후보에서 제외. unrelated repo를 오묶을 수 있음 |
| 토큰/비용/성능 점수 | 순위·우열·조직 | 공간 그룹 기준으로 사용하지 않음 |

## 5. 사무실 공간 계약 — 동적 가구 v2

최신 사용자 요청에 따라 v1의 6자리 층·고정 배경 책상·첫 보조 동료만 표시하는 규칙을 대체한다.

- 프로젝트가 팀이다. 같은 Git common-dir 또는 canonical cwd의 동료를 하나의 바닥 구역에 모으고, 바닥에 프로젝트명·인원을 적는다. 브랜치는 각 책상 앞면에 표시한다.
- 책상·의자·모니터·캐릭터는 배경에 포함된 그림이 아닌 독립 배치 요소다. `layoutOffice`가 프로젝트 구역·공동 책상·주 좌석·보조 책상의 좌표와 크기를 만든다. 장식용 소파·카펫·미사용 책상은 주 사무실 공간을 차지하지 않는다.
- 같은 프로젝트 + 같은 worktree + 같은 브랜치/커밋 근거는 긴 책상으로 연결한다. 근거의 기록/현재 출처까지 키에 포함하며, 브랜치도 커밋도 모르면 독립 책상으로 둔다. 다른 브랜치는 같은 팀의 이웃 책상이다.
- 층/페이지당 6명 제한은 없다. 사무실 상태인 모든 주 세션과 모든 보조 세션을 한 공간에 배치하고 기본 배율을 전체 보기에 맞춘다. 실제 화면 비율에서 가구가 최대한 크게 보이는 열 수를 선택한다. 인원이 많으면 작아지므로 확대·스크롤·전체 보기 복귀를 제공한다.
- SQLite `office_seats` 숫자는 안정적인 순서 토큰이다. 2, 6, 12 같은 기존 희소 번호는 빈자리/층을 의미하지 않는다. 신규 세션은 빈 순서 토큰을 사용한다.
- 상태·메시지·최근 사용·열람 빈도·명단 검색/정렬로 가구를 움직이지 않는다. **세션 추가/제거, 부모 관계·프로젝트·브랜치 변경, 창 크기 변경**은 실제 배치를 다시 계산할 수 있다. 같은 토폴로지와 창 크기는 새로고침/재시작에도 같은 배치다.
- 오른쪽 상세를 열면 가구 좌표를 유지하고 배율만 바꾼다. 데스크톱에서는 명단 자리를 상세창에 양보해 방을 계속 볼 수 있게 한다.
- 실제 subagent/child는 주 작업 아래 낮은 보조 책상을 각각 가진다. 첫 동료만 남기거나 나머지를 숨기지 않는다. 중첩 관계는 주 작업 기준으로 평탄화한다. 부모가 없거나 다른 공간이면 독립 자리로 접근한다.
- 데스크 펫은 사무실 구역 주 동료 중 할 일 순서(나를 기다려요 → 확인할 결과 → 일하는 중 → 쉬는 중)의 첫 동료 캐릭터와, 가장 급한 그룹·인원 하나만 보여 준다. 누르면 펫이 있는 화면의 작업 영역 하단 전체 폭에 **책상 줄**로 펼쳐진다. 책상 줄은 큰 사무실과 같은 토폴로지(`officeTopology`)를 한 줄로 놓는다. 프로젝트 구역이 나란히 서고, 같은 worktree·브랜치는 긴 책상 하나를 쓰며, 보조 동료는 그 책상 바로 뒤의 낮은 책상에 앉는다. 말풍선은 큰 사무실과 같은 `stationSpeech` 규칙을 따른다. 인원 제한은 없다. 책상은 큰 사무실 100% 크기로 고정하고 인원이 늘어도 작아지지 않는다. 화면을 넘치면 양옆 화살표(숨은 인원 수, 기다리는 동료가 있으면 표시)와 가로 스크롤·←/→로 한 화면씩 넘긴다. 줄은 화면 끝에서 끝까지 쓰고, 도구는 말풍선 위 투명 띠에 둔다. 줄에서는 말풍선을 5줄까지 보여 준다. 할 일 순서는 펫의 대표 선택에만 쓰고 자리를 바꾸지 않는다. 펫 요약은 명단과 같이 보조 동료도 각자 센다(보조의 확인 요청도 펫을 부른다).
- **가리기**: 큰 사무실·책상 줄에서 동료에 마우스를 올리면 눈 버튼으로 가릴 수 있다. 가린 시각(`hiddenAt`, 개인 상태)은 서비스가 직접 찍어(`veil` 요청, 한 트랜잭션) 별명·고정과 같은 저장소에 남긴다. 그 이후 **다음 대화**(새 요청·최종 응답·확인 요청/오류 소식, 또는 요청/응답 진행 설명)가 생기면 저절로 다시 보인다. 진행 메모, background 소식, 같은 페르소나의 예약·내부 실행과 보조 세션의 대화로는 풀리지 않는다. 사무실로 데려오면(`returnedAt`) 바로 보인다. 부르는 동료(할 일 그룹 attention, 보조 포함)에게는 눈 버튼이 없고, 가려져 있어도 바로 보인다. 가린 동료는 J/K 이동과 명단 스포트라이트에서도 빠진다. '모두 다시 보기'는 가림 시각이 있는 모든 세션을 지운다. 가린 동료와 그 보조 책상은 장면과 펫 요약에서 빠지지만 명단·검색·소식함에는 남는다. 큰 사무실 하단 '가린 동료'와 책상 줄 '가림 n'에서 바로 되돌린다.
- **펫 말풍선**: 가리지 않은 동료에게 2분 안에 도착한 미확인·미열람 중요 소식(최종 응답·확인 요청·오류, bootstrap·접음 제외)이 있으면, 확인 요청을 먼저, 그다음 가장 최근에 도착한 것의 동료가 펫이 되어 같은 `SpeechBubble`로 말한다. 펫을 깨운 바로 그 소식을 말하고(도착 시각 기준 최신), 펫 아래 이름표를 단다. 마우스를 올리면 말풍선이 펼쳐지며 이름·상태·프로젝트·브랜치·미확인 수를 보여 준다. 열기는 큰 사무실의 그 세션, 접기는 말풍선 접기 receipt. 2분이 지나면 평소 대표로 돌아온다.
- **말풍선 펼치기**: 내용이 잘리면 말풍선 아래 탭으로 그 자리에서 전문을 펼친다(길면 말풍선 안에서 스크롤). 펼치면 글 길이에 맞춰 옆으로도 넓어진다(큰 사무실 240·책상 줄 260·펫 280px까지). 큰 사무실·책상 줄·펫 공통.
- **말풍선 종류**: 말의 종류마다 모양이 다르다(`stationSpeech().tone`).
  - 내 요청: 어두운 바탕, 오른쪽 꼬리
  - 생각 중: 구름과 동그라미 꼬리, 기울임
  - 진행: 점선 메모와 타이핑 점
  - 최종 응답: 파란 완료선
  - 응답 필요: 빨간 굵은 테두리와 맥박
  - 확인 필요: 노란 경고 줄무늬
  - 그 밖: 회색 메모
  - 읽음은 모든 모양에서 흐린 테두리로 같고, 움직임 줄이기를 따른다
- **고정**: 책상에 마우스를 올리면 눈 버튼 아래에 핀 버튼이 나온다. 고정하면 오래 지나도 대기·보관으로 옮기지 않고(`pinned`), 고정된 책상은 핀이 늘 보인다.
- **말풍선 원문**: 말하는 공개 메시지의 원문이 snapshot에 있으면(최근 4개 + 말하는 메시지) 그 원문을 인라인 스타일(굵게·기울임·코드·`~~취소선~~`)로 보여 준다. 한 글자 `~`는 글자 그대로다. 코드 블록·링크·이미지는 그리지 않는다. 원문이 없으면 저장된 요약을 쓴다. 저장되는 소식 요약(`messageExcerpt`)은 바꾸지 않는다(소식 버전이 바뀌어 지난 소식이 다시 울리지 않도록).
- 4시간 무활동 → 대기 라운지, 7일 → 보관. 핀은 자동 이동 방지. 읽지 않은 소식은 공간 이동으로 삭제하지 않는다.

### Git 표시 근거

원본 `Session.branch`와 `gitCommit`은 기록 당시 정보다. `workspace.git`는 로컬 Git을 읽기 전용으로 확인한 현재 관측이며 branch/commit/state/observedAt을 갖는다. 15초 캐시로 반복 명령을 제한한다.

- 기록에 이름이 있으면 그 이름을 표시한다.
- 이름 대신 커밋만 기록되어 있으면 `커밋 · abc1234`; 현재 detached HEAD가 그 커밋과 같으면 `HEAD · abc1234`.
- 기록에 둘 다 없고 현재 이름만 확인하면 `main · 현재`처럼 출처를 표시한다.
- 현재 detached HEAD는 `HEAD · abc1234`; Git 저장소가 아닌 위치는 `작업 폴더`; 근거가 없으면 `브랜치 기록 없음`.
- TaskDeck의 2f06/836c worktree는 실제 detached HEAD였다. 이름이 누락된 과거 기록에 main/가장 가까운 브랜치를 추측해 넣지 않는다. `name-rev`, 원격 fetch, checkout 변경을 하지 않는다.

### 퇴근·보관 설정

‘사무실 설정’에서 마지막 활동 후 대기까지 1시간~90일, 보관까지 1~365일, 자동 보관 여부를 선택한다. UI는 자주 쓰는 시간/일 선택지를 제공하며 기존 저장값도 표시한다. **두 시점 모두 마지막 활동을 기준**으로 하고, 보관은 대기보다 늦어야 한다. 예: 대기 3일/보관 14일이면 3일째 라운지로, 라운지에서 11일 후 보관한다. 보관까지를 라운지 입장일부터 세지 않는다.

자동 보관을 끄면 오래된 동료도 대기 라운지에 머문다. 직접 보관은 그대로 적용되고, 핀은 자동 이동을 막는다. 기존 기본값 4시간/7일은 유지한다. 대기 시간을 보관 시점보다 길게 올리면 UI는 보관 시점을 대기 다음날로 맞추고 현재 요약에 표시한다. 잘못된 조합의 API 요청은 저장하지 않는다. 원본 기록·소식·개인 메모를 삭제하는 설정이 아니다.

### 할 일 흐름 (v6 · UX 계약)

사용자가 앱을 여는 이유는 ① 누가 나를 기다리는가 ② 자리를 비운 사이 무엇이 끝났는가 ③ 지금 누가 무엇을 하는가 ④ 예전 맥락 이어받기다. 표현은 이 순서를 따른다. 정본 코드는 `src/shared/triage.ts`.

- **명단 = 할 일 순서**. 사무실 명단은 `나를 기다려요(호출·오류·미해결 확인 요청) → 확인할 결과(중요 소식 미확인) → 일하는 중(최근 작업 근거) → 쉬는 중`으로 묶는다. 그룹은 배타적이고, 각 그룹 안에서는 사용자가 고른 정렬을 유지한다. 라운지·보관 명단은 할 일 목록이 아니므로 묶지 않는다.
- **요약 숫자는 겹칠 수 있는 사실**이다(일하는 중이면서 결과가 남은 동료). 숫자를 누르면 해당 첫 행으로 이동·강조한다. 결과 그룹의 ‘모두 읽음’은 표시된 최종 응답만 읽음 처리하고 확인 요청은 남긴다.
- **명단 ↔ 사무실 연결**. 명단 행에 올리면 그 책상을 스포트라이트하고 나머지를 흐리게 한다. 책상에 올리면 명단 행만 강조한다(방은 흐리지 않음). 확대 상태에서 동료를 고르면 그 책상으로 스크롤한다. 어떤 강조도 가구 좌표를 바꾸지 않는다. HUD의 ‘불러요 N’은 기다리는 동료를 차례로 고른다.
- **업무 카드의 ‘지금’ 카드**는 탭 위에 고정한다(대화가 최신 메시지로 스크롤돼도 보이도록). 상태별 다음 행동: 확인 필요 → 원래 앱 재개(재개 명령 복사/Codex에서 열기)와 ‘답변은 원래 앱에서’ 안내, 새 결과 → 결과 발췌·읽음·소식 보기, 작업 중 → 관측된 작업 시작부터의 경과 시간, 그 외 → 최근 활동. 확인 필요일 때는 하단 주 버튼도 재개로 바뀐다. 앱이 답변·승인을 보냈다고 표현하지 않는다. 결과 카드의 ‘더 보기’만 열람(`view`)으로 기록하고, 카드가 보이는 것만으로는 기록하지 않는다. 짧은 창에서는 한 줄 요약으로 접는다.
- **경과 시간**은 `taskStartedAt`(공개 요청/turn 시작 근거)이 있고 최근 작업 근거가 있을 때만 표시한다. 없는 시작 시각을 추정하지 않는다.
- **⌘K 명령 팔레트**는 사무실을 떠나지 않고 동료(할 일 순서 우선)·기록 검색·이동/설정 행동을 연다. 일치하는 명령이 전체 검색보다 위에 온다. 숨기기 모드에서는 이름·발췌 검색을 하지 않는다. 깊은 검색은 기억 서랍으로 넘긴다.
- **키보드**: J/K 할 일 순서 이동, R 선택 동료의 미확인 소식 읽음, I 소식함, 1/2/3 공간, F/+/− 전체 보기·확대·축소, ? 도움말, / 또는 ⌘K 팔레트. 입력 중·대화상자 열림에는 한 글자 단축키를 무시한다. 연속 J/K 동안은 순서를 고정해 읽음 처리로 커서가 뒤섞이지 않게 한다.
- **자리 비운 사이 요약**: 창이 2분 이상 비활성/숨김 후 돌아오면 그 사이 `receivedAt`이 새로운 미확인 중요 소식만 요약한다(bootstrap 제외). 한 동료면 바로 열고, 여럿이면 소식함으로 보낸다. 탭 제목에 미확인 중요 소식 수를 표시한다. OS 알림·Dock 배지는 후속 후보다.
- 오른쪽 패널은 동료/소식 두 탭으로 한 번에 오간다. 업무 카드는 같은 자리를 쓰며 닫으면 명단으로 돌아온다.

### 대화 종류 선택

- 대화의 전체 / 내 요청 / 진행 상황 / 최종 응답 버튼은 독립적인 필터다. 원본이 단계를 제공하지 않으면 기타 응답 버튼을 추가하고 완료라고 추측하지 않는다.
- 같은 라벨을 개별 말풍선에도 표시한다. 전체에서도 요청은 사용자, 진행은 파란 표식, 최종 응답은 초록 표식으로 구별한다. 색만으로 의미를 전달하지 않는다.
- Codex commentary와 final/final_answer, Claude/OpenClaw의 end_turn/stop 완료, tool_use/toolUse 또는 함께 있는 도구 호출 블록의 진행 근거를 공통 OfficeEvent.phase로 변환한다. 출처 없는 메시지를 현재 세션 mood나 시간 경과로 완료로 승격하지 않는다.
- 도구/결과/lifecycle 기록은 기본 숨김, 전체 대화에서 도구 기록 포함을 선택하면 접힌 묶음으로 표시한다. 내부 analysis/reasoning은 이 옵션에도 나타나지 않는다.
- 종류를 바꿔도 말풍선의 더 보기 상태는 세션 내에서 유지한다. 새 기록이 도착해도 사용자가 고른 필터를 바꾸지 않는다. 필터를 바꾸면 선택한 종류의 최근 기록으로 이동한다.

## 7. 소식과 읽음 계약

- SQLite에 `event ID + session ID` 단위로 저장한다. 원본 관측, 사용자의 읽음, 말풍선 접기는 별도 상태다. 앱/브라우저 새로고침과 재시작 후 유지한다.
- 공개 진행 메시지, 최종 응답, 단계 불명 응답, 사용자 요청, 명시적인 입력 요청을 소식 기록으로 수집한다. `error`는 규격에 예약되어 있으며 원본의 명시적 최종 오류를 보장하는 어댑터가 생길 때 사용한다. 일반 exec/tool/result마다 알림을 만들지 않는다.
- 첫 도입/새 수집 세션의 과거 이벤트를 모두 알리지 않는다. 최근 3시간의 마지막 의미 있는 소식으로 초기화하고 처음 수집한 기록에는 새 업무 애니메이션을 재생하지 않는다.
- 이후 새 공개 메시지는 개별로 저장. 동일 메시지의 스트리밍 업데이트는 동일 소식을 갱신한다. 도구 기록/폴링만으로 새 소식이 생기지 않는다.
- 읽음 처리는 선택한 소식의 ID와 version만 수락한다. 현재 분류의 미확인 전체 읽음은 화면에 표시된 대상 건수에 대해 실행하며, 1,000개 단위 API 제한 안에서 나누어 처리한다. 요청 중 도착한 새 버전/새 메시지는 읽음으로 소실되지 않는다.
- 소식에는 **처음 도착 / 열어봄 / 읽음**을 구분한다. 말풍선을 눌러 열거나 소식의 더 보기·원문 세션 열기를 누르면 그 ID/version에 `viewedAt`을 남긴다. ‘읽음’은 별도 버튼으로만 확정한다. 단순 화면 노출·스크롤·마우스 올림·패널 전체 열기는 열람 증거로 삼지 않는다. 화면 내용 숨기기 중에는 자동 열람을 기록하지 않는다.
- 말풍선은 기본 **3시간** 유지. 읽었다고 즉시 사라지지 않음. X는 말풍선만 접고 미확인 수는 유지한다. 설정한 시간이 지나면 일반 말풍선은 사라져도 미확인 소식함에 남는다.
- 현재 최신 말풍선이 미해결 응답 필요/오류라면 3시간이 지나도 유지한다. 다른 최신 소식으로 바뀌어도 미해결 호출은 소식함·상태 표식에서 접근한다. 새 사용자 입력/새로운 명시 상태로 해결된 호출은 과거 소식으로 남기며 현재 승인 요청처럼 표현하지 않는다.
- 기본 소식함은 **완료 근거가 있는 최종 응답만** 표시한다. 확인이 필요한 질문은 별도 버튼과 안내로 항상 접근할 수 있다. 사용자 요청·중간 진행·단계 불명 응답은 전체 기록에서만 표시하고 기본 알림 숫자에 더하지 않는다.
- 공통 `isInboxNotice`/`unreadNoticeCount`를 상단, 책상, 보조 책상, 미니, 상세, 서비스 noticeStats 모두에 사용한다. `reply`이면서 `phase=final`인 일반 대화 또는 미해결 attention/error의 미확인 건수다. 보조·자동 최종 응답은 전체 기록에 남고 중요 숫자에서는 제외한다. 해결된 질문은 전체 기록에는 남고 현재 알림 숫자에서는 제외한다.
- 소식함은 최종 응답 / 확인 필요 / 전체 기록을 선택하고, 읽은 소식 포함·선택한 분류의 일괄 읽음을 제공한다. 기본 필터에서 숨긴 기록을 삭제하거나 자동 읽음 처리하지 않는다.
- 기존 소식 중 phase가 없는 reply는 완료가 확인된 것으로 취급하지 않는다. 현재 수집 구간에서 동일 시각/본문을 다시 확인하면 분류만 보완하고 읽음/접기 상태를 유지한다. 구간 밖 미검증 응답은 전체 기록에 남긴다.
- 말풍선은 원본 시각 기준 **최신 소식 한 개**다. 새 공개 진행이 오면 과거 최종 응답보다 먼저 표시한다. X로 닫거나 유지 시간이 끝나도 이전 말풍선을 다시 꺼내지 않는다. 새로운 메시지/내용 버전은 다시 표시한다. 같은 이벤트가 갱신되면 새 내용의 도착 시각부터 유지 시간을 계산하고 열람·읽음·접기를 초기화한다. 과거 미확인 기록은 소식함에 남는다.
- 읽지 않은 소식은 시간만으로 삭제하지 않음. 확인한 소식은 최근 30일간 목록에 표시하며 DB에서 자동 삭제하지 않는다; 수집 범위 밖 세션의 소식은 원본 재연결 전 숨겨도 DB의 확인 상태는 보존.
- 화면 내용 숨기기에서는 소식 본문, branch/path/관계 이름, tooltip, 예시 아닌 링크 제목까지 같은 규칙 적용.

## 8. 실행 상태와 귀여운 동작은 별개

| 관측/제품 상태 | 동작 | 전환과 제한 |
| --- | --- | --- |
| 새 실제 요청 | 봉투 도착, 짧은 인사, 자리로 돌아오기 | 새 event ID를 관측했을 때 한 번. reload·폴링·bootstrap 금지 |
| working | 타이핑·작업 중 표식·밝은 모니터 | 원본 작업 근거가 있을 때. 실제 처리율 숫자 생성 금지 |
| thinking | 생각하는 모습 | 공개 상태만, 내부 reasoning 텍스트 표시 금지 |
| needs-input | 손들기/작은 호출 표식 | read와 원래 앱에서의 답변은 다름 |
| responded | 결과 봉투/응답 완료 | 업무 성공 아님. 응답이 지나면 장식 휴식으로 |
| interrupted | 조용히 쉬기 + 상세 중단 근거 | 자동 오류로 몰지 않음 |
| error | 차분한 확인 표식 | 오류 로그 한 줄만으로 최종 실패 확정하지 않음 |
| quiet/stale | 기지개, 자리 옆 짧은 산책, 휴식, 졸기 | 표시는 장식. 프로세스 정지/실제 다른 행동을 주장하지 않음 |
| waiting/archive | 프로젝트 이름표·소파/침대에서 휴식 / 보관된 기록 | 아직 읽지 않은 소식은 유지 |
| 연결 오류/일시정지 | 공간 상단 연결 상태 | 개별 세션을 실패/잠듦으로 덮어쓰지 않음 |

동작은 자신의 구역 안에서 작게, 책상 소유권은 고정한다. 선택하거나 새 작업이 오면 제자리. 배경 탭·움직임 줄이기에서는 이동/점멸을 멈추고 상태 아이콘만 유지한다. 키보드 접근은 애니메이션을 기다리지 않는다. 기본 알림음 없음.

### 에셋과 꾸미기 확장

책상, 의자, 보조 책상, 장비, 침대, 소파, 펫을 독립 에셋으로 렌더링한다. 배치 엔진은 좌표·크기·연결만 담당하고 팔레트/스킨은 세션 정체성과 원본 상태를 변경하지 않는다. 현재는 팔레트와 펫 색상·소품 슬롯을 코드 계약으로 지원한다. 사용자가 꾸미기를 저장하는 편집 UI는 아직 제공하지 않는다. 구현·후속 저장 키/범위는 [에셋 확장 계약](../development/OFFICE-ASSETS.md)을 따른다.

## 10. 변경 시 필수 검증

1. 동일 원본의 여러 파일 조각은 1명, 실제 fork/subagent는 서로 다른 동료로 유지.
2. 자동 첨부 컨텍스트만 있는 입력은 제목·활동·새 요청을 만들지 않음.
3. Claude/Codex/OpenClaw에서 같은 공통 입력은 같은 그룹·소식·표현 결과.
4. 다른 repo/branch/worktree의 오그룹 방지, 미확인 값의 명시, 부모 누락/순환 안전 처리.
5. 정렬·상태·폴링·재시작으로 좌석이 섞이지 않음.
6. 소식 read/dismiss 분리, 오래된 미확인 유지, 중복/스트리밍 처리, 늦게 도착한 메시지 보존.
7. 상세를 열어도 사무실 클릭 가능, 메모 초안/펼침/스크롤 유지, 좁은 폭과 키보드 접근.
8. 개인정보 모드, 움직임 줄이기, collector 끊김에서도 사실 의미가 변하지 않음.
9. 골든 문서의 규칙과 구현·테스트·배포 상태를 구분해 기록. 후보를 구현 완료로 쓰지 않음.

## 11. 구현 범위와 확장 기준

- 공통 규격의 구체적인 필드와 어댑터 확장 절차는 [관측 규격 구현 정책](OFFICE-OBSERVATION-PROTOCOL.md)을 따른다.
- v1에서 구현: 3종 원본의 같은 규격 변환, 대화 조각 병합, 부모/분기 관계, Git common-dir/worktree 확인, 고정 공동 책상과 보조 책상, 도킹 상세, SQLite 소식/확인 상태, 3시간 말풍선, 새 요청 효과, 자리 옆 장식 휴식.
- 기존 자리의 재정렬은 하지 않는다. 따라서 기존에 흩어진 같은 팀은 즉시 합쳐지지 않을 수 있다. 비어 있는 자리의 신규 배정에 팀 정책이 적용된다.
- 본문 없이 제목·도구 기록만 있는 공급자는 진행 설명을 만들어 채우지 않는다. 파일의 처음/최근 구간만 읽는 수집 범위는 그대로이며, 읽지 못한 구간의 모든 메시지가 소식함에 있다는 의미가 아니다.
- 여러 호스트의 정체성, 공급자별 공식 실행·승인 API, 전체 transcript 백필, 소식 서버 페이지네이션과 장기 대용량 운영은 후속 범위다. 현재 읽음/접기 상태는 로컬 앱 DB에 공유되므로 같은 사무실을 보는 브라우저들에 공통 적용된다.


## 수집 모듈 재사용과 동일성 불변식 (2026-10-04 추가)

상세 근거는 [수집 레퍼런스 감사](../research/INGESTION-REFERENCE-AUDIT.md). 레퍼런스 조사와 실제 코드 편입을 구별해서 기록한다. provider 어댑터가 네이티브 대화 ID/관계를 결정한 뒤 공통 병합에 전달한다. 파일명은 transport 식별자이며 대화 ID를 덮어쓸 수 없다. 프로젝트/branch/이름이 같다는 이유로 서로 다른 대화를 병합하지 않는다. Claude 자식 ID는 부모 범위, OpenClaw ID는 agent 범위에 속한다. event ordinal은 파일마다 재사용될 수 있으므로 전역 event ID로 쓰지 않는다. 파서 변경 때 읽음/닫음 상태의 호환성을 검증한다.

외부 모듈은 vendor 원본·실행본·커밋·라이선스·수정 범위와 원본 테스트를 함께 관리한다. 전체 파서가 자식을 숨기거나 제어/네트워크 부수효과를 동반하면 필요한 읽기 함수만 편입한다. 공통 관측 규격과 사무실 표현 정책을 외부 앱의 정책에 맞춰 변경하지 않는다.

대화의 현재 원본 수집 구간에서 빠진 공개 메시지는 해당 세션의 저장된 소식으로 보완할 수 있다. 이때 `OfficeEvent.excerpt=true`로 표시하고 화면에 **보관된 발췌 · 원문 일부**를 명시한다. 원본 이벤트가 있으면 항상 원본을 우선하며 이벤트 ID 또는 같은 종류/phase/본문·시각으로 중복을 막는다. 공개 발췌는 원문 전체인 것처럼 표현하지 않는다. 최종 응답 필터를 선택하면 마지막 해당 응답의 시작 부분으로 이동한다.
