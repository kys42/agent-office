# 프로젝트 맥락과 의사결정

정리 기준: 2026-10-05. 대화에서 확정된 요구와 구현 근거를 다음 작업에 전달하는 문서다. 개인 대화 원문이나 에이전트 내부 추론을 보관하는 문서는 아니다.

## 제품의 중심

Claude Code, Codex, OpenClaw에서 진행하는 실제 작업을 한 사무실에서 이해하고, 에이전트를 눌러 요청·진행·결과와 작업 기억을 이어받는다. 설치된 실행 파일 목록보다 **실제 로컬 세션과 공개 활동**이 중심이다. 공급자별 로그 포맷은 어댑터에서 끝내고 사무실은 하나의 공통 규격을 읽는다.

사용자가 선택한 시안 E는 [원본 기획](../../references/design-source/docs/01-brief.md)과 [디자인 컨셉](../../references/design-source/docs/02-design-concepts.md)에 있다. 원본 출처는 `kys42/claude-skills`의 `claude/agent-desktop-pet-design-9aex2v` 브랜치, 조사 당시 커밋은 `9a644d65e651e55213af2fe409d09e37f12a849e`다. 현재 앱은 별도 `kys42/agent-office` 프로젝트다.

사용자 첨부 `agent_office_feature_catalog_2026-10-03.pdf`는 140개 기능 후보를 가진 조사 자료였다. 모든 후보의 구현 완료를 뜻하지 않는다. 원본 PDF 자체는 이 저장소에 포함하지 않았으며, 채택·미채택 범위는 아래 문서와 골든 정책에 기록한다.

## 2026-10-05 추가 결정

- OpenClaw는 사용자가 선택한 **페르소나별 한 명 + 내부 실행 기록**으로 표시한다. 원본 대화 ID는 별도 유지한다.
- 일반 보조 작업은 완료 후에도 현재 메인 작업의 결과 확인용으로 남기고, 메인의 다음 요청 또는 메인의 대기/보관에서 접는다. Codex 내부 실행은 접힌 기록으로 남긴다. 사용자 확인이 필요한 작업은 드러낸다. Guardian이라는 제목으로 판별하지 않는다.
- 최신 공개 진행은 바로 말풍선에 반영한다. 최신 말풍선을 X로 닫으면 이전 것을 재생하지 않는다. 이전 소식은 소식함에 남긴다.
- 처음 도착/직접 열어봄/읽음은 별도 상태. 화면 노출만으로 열어봤다고 추측하지 않는다. 말풍선에서는 글자 대신 미확인 점(처음 도착·열어봄)과 흐린 테두리(열어봄·읽음)로 그리고, 글자는 스크린리더와 툴팁에 남긴다.
- 퇴근/대기와 보관은 마지막 활동 후 시간·일로 설정하고 자동 보관은 끌 수 있다.
- 라운지는 이름과 프로젝트가 붙은 소파/침대 휴식 공간. 책상·펫·소품은 독립 에셋으로 분리하며 사용자가 직접 꾸미는 저장 UI는 후속 범위다.

## 유지해야 할 구분

- 플랫폼 연결 상태, 기록에서 관측한 실행 상태, 시간에 따른 휴식 표현은 서로 다르다. 관측 중인 작업 세션의 프로세스를 직접 제어하거나 실행 생존을 보장하지 않는다. 별도로 생성하는 오피스 매니저의 전담 실행 수명은 앱이 관리한다. 예외는 ‘터미널로 보내기’ 하나로(데스크탑 기본 켜짐, 설정에서 끌 수 있음), 사용자가 직접 보낸 글을 쉬는 Claude Code 세션의 Orca·tmux 터미널에 입력하거나 Codex CLI 세션의 대기열(`codex queue`)에 넘기는 것뿐이다.
- 같은 프로젝트로 **그룹화**하는 것과 동일 대화로 **병합**하는 것은 다르다. 프로젝트·브랜치·제목이 같다고 세션을 합치지 않는다.
- 세션 기록 당시 Git 정보와 지금 checkout의 Git 정보는 다르다. detached HEAD를 임의의 브랜치 이름으로 바꾸지 않는다.
- `final`은 해당 응답의 완료 근거다. 전체 업무 성공·테스트 성공·사용자 결과 확인을 의미하지 않는다.
- 사무실 책상의 순서는 안정적이지만 물리 좌표의 영구 고정은 아니다. 인원·프로젝트·관계·창 크기가 바뀌면 공간을 다시 계산할 수 있다.
- 로컬 검증과 서명·공증된 프로덕션 배포를 구분한다. 현재 macOS arm64 패키지는 로컬 실행 산출물이다.

## 대체된 결정

초기의 파일명 UUID 우선 식별, 6자리씩 나눈 사무실, 배경에 고정된 가구, 첫 보조 동료만 표시, 도구명을 주 활동으로 표시하는 방식은 현재 정본이 아니다. 과거 작업 기록에 남아 있어도 새 구현의 기준으로 복원하지 않는다.

9개 테마 시안은 비교용 결과물이다. 테마 전체 중 특정 안이 최종 채택되었다고 가정하지 않는다. 현재 제품은 시안 E 계열의 캐릭터·사무실에서 동적 가구 구조로 발전했다. 사용자 요청 없이 페이지 구조 전체를 새 테마로 바꾸지 않는다.

공식 hook/이벤트 스트림(구조화된 답하기는 #127 3단계 후보), 자동 승인(하지 않음. 사람이 켜고 누르는 키 입력 답하기만 2026-10-13 채택, 쉬는 세션의 후속 입력은 2026-10-06 터미널 보내기로 채택, 2026-10-07부터 기본 켜짐), 새로운 플랫폼, 자동 열람 확인, 프로젝트 별칭, 계정 기반 원격 기기 통합, AI 요약·의미 검색, 예약 회고, 장기 캐릭터 성장, 서명·공증·자동 업데이트는 후속 후보다. 이미 구현된 것처럼 버튼이나 상태를 만들지 않는다. 구체적인 후보와 채택 기준은 [골든 정책](GOLDEN-OFFICE-POLICY.md)에 유지한다.

## 후속 작업자가 시작할 때

1. [문서 지도](../README.md)에서 해당 계약과 [수집 출처](../research/INGESTION-REFERENCE-AUDIT.md)를 읽는다.
2. 세션 중복은 identity/merge, 잘못된 상태는 normalize/runtime, 배치는 office/layout, 대화·소식은 conversation/notices/store 경계를 먼저 확인한다.
3. 원본 형식이 달라졌으면 개인 원문을 복사하기보다 최소 합성 fixture로 재현하고 해당 테스트를 추가한다.
4. 현재 실행 중인 preview의 데이터·프로세스를 보존한다. 검증에는 별도 임시 디렉터리나 합성 데모를 사용한다.
5. 제품 정책·원본 출처·테스트 근거를 같은 PR에서 갱신한다. 리서치 clone이나 기억에만 있는 결정을 정본으로 삼지 않는다.


### 2026-10-05 · 동료의 작업량과 실제 작업 위치

사용자가 구독 한도·세션 누적 비용·서류 도착/집중 연출·다른 worktree에서 실제 작업 중일 때의 표시를 요청했다. 한도는 계정 단위 버튼 조회, 비용은 관측 장부의 API 기본 단가 환산, 위치는 명시 실행 인수+로컬 Git 검증으로 채택했다. PR branch를 무조건 따라가거나 단순 파일 read만으로 이동하지 않는다. 표준 규격과 표시를 공급자와 분리한다. [구현과 한계](../development/USAGE-AND-WORKSPACE.md).

### 2026-10-07 · ‘터미널로 보내기’ 기본 켜짐

사용자가 데스크탑의 ‘터미널로 보내기’를 기본으로 켜 두기로 결정했다(그전에는 기본 꺼짐·opt-in). 설정 파일이 없으면 켜진 것으로 보고, 사용자가 끈 선택만 데스크탑 프로필에 남긴다(읽을 수 없는 파일은 꺼짐). 다시 켤 때는 예전처럼 네이티브 확인창을 거친다. 권한 승인은 보내지 않고, Claude는 터미널 전면을 가진 쉬는 세션에만 입력하며, Codex는 살아 있는 Codex CLI 세션의 대기열로만 넘기는 경계는 바뀌지 않았다. 웹 미리보기와 MCP에는 여전히 없다. [터미널 연결](../development/TERMINAL.md).

### 2026-10-13 · 묻는 내용 보여 주기와 앱에서 답하기 (#127)

'불러요'인 세션이 무엇을 묻는지(질문·선택지, 플랜) 기록에서 모아 카드와 말풍선에 보여 주기로 했다. 권한 확인은 도구 입력을 저장하지 않고 도구 이름만 보이며, 무엇을 실행하는지는 데스크탑 앱이 화면에서 읽는다. 답하기는 이미 떠 있는 Claude Code 세션(Orca·tmux)에 그 대화상자의 키를 눌러 넣는 방식으로 채택했다. SDK `canUseTool`·Codex app-server는 자기가 띄운 세션에만 답할 수 있고, 세션 간 메시지는 권한 응답을 할 수 없으며, hook은 설치 후 새 세션부터라 후속(3단계)으로 남겼다. 원칙(리뷰 반영): **화면이 기준이고, 모호하면 키를 누르지 않는다.** 승인은 자동으로 보내지 않는다. 질문·플랜과 권한 확인을 따로 켜고(아직 묻지 않음·켬·끔, 처음 한 번 네이티브 확인, 데스크탑 프로필에만 저장), 화면이 그 세션의 열린 호출 정확히 하나와 글자 그대로 같고 그 호출이 카드의 요청일 때만, 한 번짜리 선택지(한 번 허락·거절·편집마다 묻는 플랜 승인)만 보낸다. 계속 적용되는 선택지(항상 허락·auto mode 등)는 터미널에서 고른다. 매 키 전에 같은 pid·대기 상태·터미널 전면 소유와 화면을, 매 키 뒤에 화면을 확인하고, 화살표는 한 번에 하나씩 누른다. 숫자·Tab·Esc는 누르지 않는다(측정: 숫자는 고르고 바로 제출, Tab은 승인 줄을 글 입력 줄로, Esc는 도구 호출 전체 취소). 에이전트별 차이(세션 찾기·화면·키·기록)는 `desktop/prompts/` 어댑터에, 공통 흐름은 `desktop/answers.ts` 한 곳에 둔다. Codex는 보여 주기만 한다. [규칙·측정](../development/TERMINAL.md#질문플랜권한-확인에-답하기-127)

### 2026-10-14 · 공통 화면 연결과 공급자별 전송

사용자는 Codex도 Orca/tmux의 원래 화면으로 이동하고 Claude와 공통 연결을 쓰길 요청했다. 전송과 이동을 분리하는 정책으로 진행을 승인했다. 공통 호스트 검증/이동을 재사용하고, Codex 전송은 `codex queue`로 유지한다. 현재 대화 ID를 확인할 수 없는 화면이나 여러 화면은 임의 연결하지 않는다. Codex 0.162.1의 32자 축약 제목 ID는 살아 있는 writer-lock의 전체 ID에 유일하게 일치할 때만 복원하고 클릭 직전에 다시 확인한다. Codex 제목 ID 설정과 구현의 한계는 [터미널 연결](../development/TERMINAL.md)에 기록한다.

### 2026-10-15 · 팝업 위치와 카드 고정 분리 (#157)

사용자는 인수인계 꾸리기를 팝업에서 빼고 기본 위치를 기억하는 기능과 다른 동료를 열어도 남는 독립 고정을 따로 두는 구조를 승인했다. 위치 기억은 일반 팝업의 로컬 좌표, 카드 고정은 현재 대화의 창 수명이다. 사무실에 동료를 남기는 기존 핀은 더보기로 옮기고, 고정 창은 서로 다른 내용·위치·초안을 유지한다. 같은 대화는 기존 고정 창을 재사용하며 재실행 시 위치만 복원한다. [팝업 카드](../development/POPUP-CARDS.md)가 구현·IPC·검수 정본이다.

## 2026-10-18 · 여러 Office 연결 베타

별도 제품 대신 기존 앱의 기본 꺼짐 베타로 채택했다. 별도 worktree에서 구현하며 기존 DB·로컬 API를 유지한다. LAN 직접 조회를 우선하고 Tailscale은 같은 프로토콜로 확장, 외부 계정 연동은 설계만 고려한다. 컴퓨터를 독립 사무실로, 프로젝트를 그 안의 구역으로 표시한다. 기존 원본 DB 쓰기 없이 관측 결과를 합성하고, 별도 전송 권한을 가진 연결에서 기존에 전송 가능한 에이전트에 채팅할 수 있다. 실행·보안·제한의 정본은 [여러 Office 베타](../development/MULTI-OFFICE.md)다.
### 2026-10-18 · 스킬 기반 전담 오피스 매니저

사용자가 MCP 등록 없이 전용 스킬을 사용하는 새 tmux 세션으로 내장 매니저를 만들고, 동료 찾기·상태 조회·구역 이동·시간/일 단위 요약을 로컬 워크트리에서 구현하도록 요청했다. 기존 작업 세션을 전환하지 않는다. 매니저 전담 실행/재연결은 Office가 관리하고, 다른 작업 세션에는 조회와 사무실 표현 동작만 제공한다. 예약 요약은 앱 실행 중 읽기 전용으로 수행하며 기본 꺼짐이다. 로컬 구현과 검증, Claude 실제 실행 미검증 범위는 [매니저 가이드](../development/OFFICE-MANAGER.md)에 기록한다.

2026-10-19 후속 결정: 매니저의 실행만 전담으로 유지하고 표현은 일반 동료와 동일하게 한다. 별도 프로젝트 구역과 완장/책상 색으로 구분하며 말풍선·소식·대화·북마크를 공유한다. 조회/동작/표현을 분리하고 검증된 상태·동료 카드를 같은 대화 안에 렌더링한다.
