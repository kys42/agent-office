# 원래 터미널로 이동·바로 보내기

[골든 정책](../golden/GOLDEN-OFFICE-POLICY.md) · [아키텍처](ARCHITECTURE.md) · [문서 지도](../README.md) · 이슈 [#8](https://github.com/kys42/agent-office/issues/8)

업무 카드에서 확인한 세션에 바로 이어서 말하고, 부르는 세션의 질문·플랜 승인·권한 확인에 답한다(선택, [아래](#질문플랜권한-확인에-답하기-127)). 데스크탑 앱 전용이다. 웹 미리보기와 MCP에는 없다.

- **Claude Code**가 Orca나 tmux 터미널에 떠 있으면 그 탭/패널로 이동하고, 입력창이 열려 있으면(쉬는 중·작업 중) 그 터미널에 입력한다.
- **Codex CLI**는 공용 데몬에 올라와 있는 세션에 `codex queue`로 전달한다. 어느 터미널에서 띄웠는지와 무관하다. 현재 화면의 대화 ID와 호스트가 검증되면 Claude와 같은 Orca/tmux 이동을 사용한다.
- **Codex Desktop**은 이미 열린 사용자 대화의 owner를 확인해 앱 IPC로 보낸다. [호환 계약과 한계](#codex-desktop-대화-전송)를 따른다.
- 같은 판단을 업무 카드와 사무실 말풍선이 함께 쓴다(`src/lib/useSendTargets.ts`). 보낼 수 있는 세션의 말풍선에는 답장 버튼이 붙는다.

## 전송 표시와 오류 복구 (#146)

업무 카드에서 보낸 글은 대화 기록에 확인될 때까지 정상 밝기의 '보냄 · 대화 기록 확인 중' 임시 말풍선으로 보인다. 실제 대기열 상태를 추정하지 않는다. 전송 시작 시각을 기준으로 원본 요청·보관된 발췌와 맞추며, IPC 결과보다 기록이 먼저 도착해도 중복을 제거한다. ×는 이 컴퓨터의 임시 표시만 숨기며 실제 메시지를 취소하지 않는다.

전송이 오류로 끝났는데 입력창에 글이 남아 있으면 `office:inspect-draft`로 현재 글을 다시 읽어 확인 창으로 복구한다. trusted main-frame·터미널 보내기 설정·세션과 현재 입력 가능한 프로세스·터미널 앞자리·에이전트 어댑터를 확인한다. 이 API는 키 입력·붙여넣기·클립보드 쓰기·Enter를 하지 않는다. 입력창이 없거나 확인에 실패하면 원래 오류와 내 초안을 유지한다. 다시 보내기는 사용자가 [지우고 내 글 보내기]를 누른 뒤 기존의 fresh 조회·정확한 글 비교·클립보드 백업·비우기·확인·전송을 거친다. 그 사이 바뀐 글은 다시 보여 주고, 글 전체가 보이지 않으면 터미널로 안내한다. 웹·MCP에는 제공하지 않는다.

## 세션에서 터미널까지

정본 `desktop/terminals.ts`. 모든 단계는 검증에 실패하면 "터미널 없음"으로 끝나고 기존 동작(재개 명령 복사)을 쓴다.

1. **세션 → 프로세스.** Claude Code가 쓰는 `${CLAUDE_CONFIG_DIR:-~/.claude}/sessions/<pid>.json`에서 `sessionId`가 같은 기록을 찾는다. 문서화되지 않은 CLI 상태라 `pid`·파일명 일치, `sessionId` 형식, `procStart`/`status` 존재, `kind: interactive`를 모두 확인한다. 살아 있는 pid라도 `TZ=UTC LC_ALL=C ps -o lstart=`가 `procStart`와 다르면 재사용된 PID로 보고 버린다. 같은 세션 기록이 여럿이면 최근 `updatedAt`부터 본다. 이 읽기·검증은 `server/adapters/claude-live.ts`에 있고, 수집기도 같은 코드로 권한 확인 대기(`waiting`)를 호출로 보여 준다([세션 수집](SESSION-INGESTION.md#claude-실행-기록과-호출-office-v11)).
2. **프로세스 → 호스트.** `ps -wwE`(인수+환경)에서 `ps -ww`(인수)를 잘라낸 나머지만 환경으로 읽는다. 인수 속 `ORCA_TERMINAL_HANDLE=…` 같은 글자는 무시된다. 값은 엄격한 정규식(`term_…`, `%숫자`, 절대 경로 소켓)만 허용한다. 환경변수는 상속되므로 **pty 소유자**로 진짜 호스트를 정한다. 부모를 따라 올라가며 같은 tty를 쓰는 동안 계속 오르고, 처음으로 다른 tty(또는 없음)에 있는 조상이 그 pty를 연 프로그램이다(`ps -axo pid,ppid,tty,comm`). 환경과 소유자는 프로세스 수명 동안 바뀌지 않아 `pid:procStart`로 캐시한다.
   - **tmux**(`TMUX`, `TMUX_PANE`)가 직접 호스트이므로 먼저 본다. 소유자가 tmux 서버이고 `tmux -S <socket> display-message -t <pane> '#{pane_tty}…'`의 tty가 같아야 인정한다. tmux 표식이 있는데 확인이 안 되면 **대상 없음**이다. Orca 안에서 띄운 tmux는 바깥 Orca 핸들을 물려받지만, 그 탭은 다른 패널이나 셸을 보여 줄 수 있다.
   - **Orca**(`ORCA_TERMINAL_HANDLE`, `ORCA_TAB_ID`)는 소유자가 `Orca.app` 프로세스이고 `orca terminal show --json`이 connected·writable·not orphaned·같은 `tabId`여야 인정한다. Orca 탭 안의 screen·zellij·nvim `:terminal`에서 띄운 Claude는 핸들을 물려받아도 소유자가 달라 제외된다. 라벨은 탭 제목이다. 탭 제목만으로 매칭하지 않는다(실측에서 제목과 세션 이름이 다른 경우가 있었다).
3. **렌더러에는 `TerminalTarget { kind, label, status, canSend, canFocus, queues?, desktop? }`만** 보낸다. handle·소켓·pane은 넘기지 않고, main이 이동·보내기마다 다시 찾는다. 반복 조회가 가볍도록 세션 기록 디렉터리는 1초, 호스트 확인(Orca CLI)은 15초 재사용한다. 이동·보내기는 캐시 없이 새로 확인하고 보낸 뒤 캐시를 지운다.

Ghostty·Warp·VS Code 내장 터미널 등 위 두 호스트 밖에서 실행한 Claude 세션은 이동·보내기 대상이 아니다.

## Codex CLI: 대기열로 전달

정본 `desktop/codex-queue.ts`. Codex CLI(0.158~)의 터미널 화면은 앱 서버의 클라이언트다. 서버는 보통 공용 백그라운드 데몬(`codex app-server --managed-daemon`)이고, `-c` 같은 실행 옵션을 주면 화면이 내장 서버로 뜬다(화면 경고: "command-line configuration overrides … requires embedded mode"). 전송은 화면 연결과 독립적이며, 어느 쪽이든 공식 명령 `codex queue --thread=<id> --message=<글>`로 Codex 공용 대기열에 넣는다. 그 세션을 맡은 서버(데몬이든 내장이든)가 가져가 처리한다.

- **실측:** 화면이 쉬는 중이면 1초 안에 사용자 요청으로 뜨고 답한다. 작업 중에 넣으면 그 작업이 끝난 뒤 별도 요청으로 처리된다(그래서 Codex는 작업 중에도 보낼 수 있다, `queues: true`). 내장 서버 모드 화면에도 전달된다. 기록 파일에 일반 사용자 메시지로 남아 수집기가 그대로 읽는다.
- **살아 있는 Codex가 맡은 세션만.** 세션을 맡은 프로세스는 `${CODEX_HOME:-~/.codex}/thread-writer-locks/<id>.lock`을 열어 둔다. `lsof -Fcn +d <잠금 폴더>`(약 0.1초)로 이름이 `codex`인 프로세스가 연 잠금만 인정한다. 잠금 파일은 세션이 끝나도 남기 때문에 존재만으로는 판단하지 않는다(실측: 종료한 세션의 잠금 파일이 남아 있었음). 아무도 맡지 않은 세션에 넣은 메시지는 다음에 그 세션을 열 때까지 처리되지 않아 "보냈는데 아무 일도 없음"이 되기 때문이다.
- **터미널 CLI 세션만:** 기록 첫 `session_meta`의 `originator === 'codex-tui'`이고 보조(subagent) 세션이 아니어야 한다. 데스크탑 앱(`Codex Desktop`)은 별도 서버를 써서 화면과 어긋날 수 있고, `codex_exec`은 답을 볼 화면이 없다. 머리말을 읽지 못한 경우(아직 쓰는 중 등)는 기억하지 않고 다음에 다시 읽는다.
- **실행 파일:** 데몬 패키지의 `app-server-daemon/releases/<최신>/bin/codex`를 먼저 쓰고, 없으면 npm 설치의 네이티브 바이너리를 쓴다. `/opt/homebrew/bin/codex`는 node 스크립트라 Finder에서 띄운 앱(좁은 PATH)에서는 실행되지 않는다.
- `--flag=값` 형식이라 `-`로 시작하는 글도 값으로 읽힌다. 명령은 성공했는데 응답에 `for thread <id>`가 없으면 "다시 보내기 전에 확인"을 안내한다(이미 들어갔을 수 있음). 실행 파일이 없으면(ENOENT) "보내지 않았어요"로 구분한다.
- **앱과 화면 이동 버튼:** Codex 앱 열기는 항상 독립된 버튼으로 유지한다. 검증된 Orca/tmux 화면이 있으면 별도 이동 버튼을 함께 표시한다. 화면 조회는 queue loaded-thread 조회와 분리하며 queue 조회 실패가 화면 조회를 생략하지 않는다. 전송 가능 여부는 별도 `canSend`로 유지한다. 화면 없음/중복/검증 실패 시 이동 행동은 Codex 앱 링크로 대체하고, 일시 조회 결과 때문에 앱 열기를 재개 명령 복사로 바꾸지 않는다.

## Codex 화면 연결 · 2026-10-14 (#148)

정본 `desktop/codex-focus.ts`. 공급자별 세션→화면 발견과 공통 호스트 검증/이동을 분리한다. `desktop/terminal-host.ts`의 `findHost`·`focusHost`를 Claude와 Codex가 공유한다. Claude의 입력 상태/화면 읽기/직접 전송은 `desktop/terminals.ts`, Codex 전송은 `desktop/codex-queue.ts`에 남는다.

- `TerminalTarget.kind`와 `queues`는 전송 방식이다. 별도 `focus { kind, label }`는 화면 이동 위치다. Codex가 Orca로 이동해도 전송 대상은 `codex`, `queues: true`이고 초안 검사나 터미널 입력을 실행하지 않는다. 렌더러에 핸들·소켓·PID를 전달하지 않는다.
- 로컬 native `codex` 중 tty가 있고 foreground에 있는 프로세스만 화면 후보로 본다. 공용 데몬의 잠금/PID/상속된 Orca 환경은 화면의 증거가 아니다. 일반 exec/보조 프로세스, 종료·일시정지·PTY 소유자 불일치·PID 재사용은 제외한다.
- Orca의 현재 `terminal show` 제목 또는 tmux의 현재 `pane_title` **첫 항목에 thread UUID 또는 Codex의 32자 축약형(29자 UUID 접두부 + `...`)**이 있어야 한다. 축약형은 살아 있는 Codex가 연 writer-lock의 전체 ID 중 하나에만 일치할 때 연결한다. 접두부 충돌·잠금 조회 실패·ID 누락은 미확인으로 보류하고, 클릭 직전에도 잠금 목록을 다시 읽는다. 데몬 잠금은 ID를 복원하는 근거이며 화면 주소의 근거가 아니다. 복원용 조회는 `lsof -Fcn -c /^codex$/`의 정상 완료만 인정하고 설정한 Codex home의 실제 writer-lock 디렉터리만 읽는다. macOS `+d`는 일부 닫힌 파일 때문에 열린 파일이 있어도 exit 1이므로 전송용 기존 조회와 구분한다([lsof exit status](https://github.com/lsof-org/lsof/blob/master/docs/tutorial.md)). `codex resume` 실행 인수, 제목/폴더 유사성, 과거 터미널 출력·대화 본문에서 ID를 찾지 않는다. 대화 전환 시 Codex가 갱신한 제목을 다시 읽는다.
- 한 대화가 두 화면에 연결되면 이동을 추측하지 않는다. 지원 화면 조회에 실패하면 후보를 삭제해 유일하다고 판단하지 않고 미확인으로 보류한다. ID 표시가 없는 제목·명시적으로 지원되지 않는 호스트는 연결 대상에서 제외한다. 64개를 넘는 후보도 미확인이다. 폴링은 2초간 같은 화면 inventory를 공유하고 클릭은 프로세스·호스트·제목을 새로 확인하고, 모든 후보 조회가 끝난 뒤 선택 화면을 다시 검증한다. 확인과 이동 사이 대화가 바뀌는 작은 race는 OS/호스트의 원자적 대화-ID 비교 API가 없어 완전히 제거할 수 없다. 이동은 입력을 보내지 않는다.

Codex에서 `/title`로 **thread-id를 첫 항목**으로 선택하고, 다음 항목은 thread-name/project-name 등 텍스트를 선택한다. 첫 ID 바로 뒤에 activity/spinner를 두면 공백 구분이 되므로 현재 parser는 연결하지 않는다. 설정 파일로 구성한다면 기존 `[tui]`의 `terminal_title` 항목을 다음처럼 편집한다(앱은 사용자 Codex 설정을 자동 변경하지 않는다).

```toml
[tui]
terminal_title = ["session-id", "thread-name", "project"]
```

`session-id`는 thread-id 표시 항목의 호환 이름이다. 기존 제목 구성과 합치되 ID를 맨 앞에 둔다. Codex 0.162.1은 ID 항목 자체를 32자로 축약하므로 전체 UUID만 허용해서는 실제 화면에 연결되지 않는다. 이미 실행 중인 화면은 `/title`에서 적용하거나 설정 후 다시 연다. Orca 탭의 사용자 지정 제목이 ID 표시를 가리면 자동 제목을 사용해야 한다.

## 말풍선 빠른 답장

설정이 켜져 있으면(기본), 보낼 수 있는 세션의 사무실 말풍선 오른쪽 아래에 답장 버튼이 붙는다(`Office.tsx`, `QuickReply.tsx`).

- **대상:** 말풍선이 보여 주는 소식의 세션이고, 소식이 없으면 그 자리의 세션이다(보조 책상 제외). 쉬거나 작업 중인 Claude 세션(Orca/tmux)과 살아 있는 Codex가 맡은 Codex CLI 세션이 해당한다. 작업 중이면 보낸 글이 대기열에 들어간다고 안내한다. 권한 확인·플랜 승인을 기다리는 Claude 세션에는 버튼이 없다.
- **쓰던 글 유지:** 답장 창은 연 순간의 세션과 대상을 기억하고 자리 단위로 그려진다. 새 말풍선이 오거나 대상 목록을 다시 받아도 닫히지 않는다. 그사이 대상이 승인 대기 등 입력을 받을 수 없는 상태가 되면 보내기만 잠긴다. 실패는 창 안과 알림 둘 다로 보인다. 답장 창이 있는 자리는 옆자리 위로 올라온다.
- **조작:** 누르면 말풍선 아래에 작은 입력창이 열린다. Enter로 보내고, Shift+Enter는 줄바꿈, Esc는 닫기다. 한글 조합 중 Enter는 무시한다. 결과는 알림으로 보이고 실패 사유는 창 안에 남는다.
- **화면 숨기기**(개인정보) 모드에서는 버튼을 숨긴다.
- **조회:** 말풍선의 세션 목록을 `office:terminals`로 60개씩 나눠 묻는다. 기록이 움직이면(가장 최근 `updatedAt`) 다시 묻고, 그 밖에는 15초마다 묻는다. 창이 숨겨지면 멈춘다. 업무 카드는 작업 중이거나 보낼 수 없는 대상이 있으면 4초마다 다시 본다. 목록이 바뀌는 동안에도 이미 아는 대상은 유지한다.
- **팝업 모드:** 펫·한 줄 사무실·바닥 책상에서 말풍선을 누르면 그 자리에서 펼쳐지고, 보낼 수 있으면 같은 답장 버튼·칸이 붙는다. 책상 도구의 "터미널로 이동"은 이동할 수 있는 세션에만 보인다. 책상이나 "팝업으로 보기"는 업무 카드(오른쪽 패널과 같은 Inspector)를 띄운다([기능 정책서](../golden/FEATURE-POLICY.md)).
- **비용:** Claude 세션 기록 폴더 읽기 1초, 전체 프로세스 표 1초, Orca 터미널 목록(CLI 1회) 5초, PID 시작 시각 확인 30초, 호스트 확인 15초씩 재사용한다. 보내기·이동은 모두 새로 확인한다. 실패한 프로세스 조사는 기억하지 않는다.

## 이동

업무 카드의 재개 버튼이 대상이 있으면 "Orca로 이동"/"tmux로 이동"이 된다(`office:jump`).

- Orca: `orca terminal switch --terminal <handle>` 후 `open -a Orca`로 앱을 앞으로 가져온다.
- Orca가 `navigated: false`를 돌려주면 이동 실패로 알린다.
- tmux: `select-window`·`select-pane` 후 그 세션의 클라이언트를 `list-clients`로 찾는다. 패널에 키는 보내지 않는다.
  - 클라이언트가 있으면 가장 최근에 쓴 클라이언트를 `switch-client -c <tty>`로 그 패널에 옮기고, 클라이언트 PID에서 부모를 따라 올라가 처음 만나는 `.app` 번들(Terminal·Ghostty·Orca 등)을 찾는다. 그 클라이언트가 보이는 창·탭을 고를 수 있으면 고른다: Orca는 클라이언트 환경의 `ORCA_TERMINAL_HANDLE`(+`ORCA_TAB_ID`)을 `orca terminal list`에서 확인한 뒤 `orca terminal switch`(원격 선택 변수 제거) 후 `open -a Orca`, Terminal·iTerm2는 AppleScript로 `tty`가 클라이언트 tty와 같은 탭(iTerm2는 세션)을 선택한다(tty는 argv로만 넘김). 그 밖의 앱이거나 찾지 못하면 `open -a`로 앱만 앞으로 가져오고, 창·탭은 고르지 못했다고 사실대로 알린다.
  - 앱을 못 찾으면(ssh, 데몬 서버 등) "패널은 바꿨지만 창을 앞으로 가져오지 못했다"고 알린다.
  - 클라이언트가 없으면(앱이 분리 상태로 띄운 `agent-office` 세션 등) macOS에서는 Terminal을 열어 `attach-session`으로 붙인다(명령은 osascript 인자로만 넘김). 다른 OS는 붙일 명령을 안내하고 실패로 알린다.
- 대상이 없으면 기존 동작: Codex 링크 열기, 그 외 재개 명령 복사.

## 바로 보내기 (기본 켜짐)

설정 **터미널로 보내기**(기본 켜짐)가 켜져 있으면 업무 카드 맨 아래에 입력창이 생긴다(`TerminalSend.tsx`, ↵ 보내기·⇧↵ 줄바꿈, 큰 사무실과 팝업 카드 공통). 끄면 실행 중이라는 안내 한 줄만 보인다.

- **설정은 데스크탑 프로필에만 있다.** 기본은 켜짐(2026-10-07 사용자 결정, 그전에는 기본 꺼짐)이다. 파일이 없으면 켜진 것으로 보고, 사용자가 끄면 그 선택을 파일에 남긴다. 파일을 읽을 수 없거나 깨져 있으면 꺼진 것으로 본다. 다시 켤 때는 확인창을 띄운다.
- **저장 위치:** 공유 `Preferences`가 아니라 Electron `userData/terminal-send.json`(0600)에 저장하고 IPC `office:terminal-send`로만 읽고 바꾼다. 웹 미리보기는 켤 수 없다(공유 스키마가 `terminalSend`를 거부, 테스트로 고정). 다시 켤 때는 main이 **네이티브 확인창**을 띄우고, 렌더러가 대신 확인할 수 없다.

- 아래는 Claude(Orca/tmux) 경로의 규칙이다. Codex는 위 데몬 대기열 규칙을 따른다.
- **입력 그대로.** 그 터미널에 사용자가 직접 친 것과 같다. 기록에 실제 사용자 메시지로 남고 수집기가 그대로 다시 읽는다. 권한 확인 없이 띄운 세션이면 그대로 실행된다는 점을 설정에 적었다.
- **입력창이 열려 있을 때만.** 프로세스 `status`가 `idle`·`busy`·`shell`(쉬는 중인데 백그라운드 셸이 도는 상태, 2.1.296 실측)일 때만 보낸다. Claude Code는 작업 중에 입력하고 Enter를 누르면 대기열에 넣었다가 이어서 반영하므로, 하는 걸 보다가 다른 지시를 보낼 수 있다(#78). `waiting`(권한 확인·플랜 승인 화면)과 모르는 상태는 거부한다. 승인 프롬프트에서 Enter가 기본 선택지(허용)를 누르는 일을 막는다.
- **화면 확인.** Claude는 승인 창을 그린 **뒤에** 기록을 쓰고, 서브에이전트가 살아 있으면 메뉴가 열려 있어도 `busy`로 남긴다. 그래서 기록만 믿지 않고 화면을 읽는다(tmux `capture-pane -p -e`, Orca `terminal read --screen`). 마지막 상자가 두 가로줄 사이의 `❯` 입력창이어야 한다(`readPrompt`). 승인 창·플랜 승인·질문은 이 상자를 대신하고, `!` 셸 모드는 표식이 바뀌며, 에이전트 보기(`←`, 자체 입력창에서 Enter가 새 세션을 띄움)·메뉴·대화 기록 보기·기록 검색(ctrl+r)은 아래 안내(`enter to …`(잘려도)·`esc to cancel|clear|close|return`·`space to reply`·`ctrl+o to toggle`·`search prompts:`·`Do you want`, 대소문자 무시)로, `@`·`/` 추천 목록은 입력창에 붙은 목록(빈 줄 전까지)의 들여쓴 `◇`·`❯` 줄로 드러나므로 모두 닫힌 것으로 본다(0열의 `❯`는 대기열 메시지·대화 기록이라 무시). 창 폭을 채운 세션 이름 가로줄(`─ 이름 ─`)도 가로줄로 본다. 긴 글은 입력창이 끝부분만 보여 줄 수 있어, 빈 입력창에 넣은 뒤 보이는 끝부분(40자 이상)이 넣은 글의 끝과 같으면 통과한다. tmux 창이 스크롤(복사 모드) 중이면 Enter를 tmux가 가져가므로 역시 닫힘이다. 글을 넣기 전에는 입력창이 비어 있어야 하고(안내 문구 `Try "…"`·`Press up|Enter to …`와 tmux에서 흐리게 그려진 추천 글은 빈 것으로 봄, 메인 입력창 자체 안내 `esc to interrupt`·`ctrl+t to hide tasks`는 막지 않음 — 기본 설정의 작업 중 footer. 쓰던 초안이나 실패한 보내기가 남긴 글이 있으면 섞지 않고 [아래](#입력창에-이미-글이-있을-때-94)처럼 먼저 보여 준다), Enter 직전에는 입력창이 넣은 글과 **정확히 같아야** 한다(공백·줄바꿈·이모지 변형 선택자 무시, 긴 붙여넣기는 `[Pasted text #N …]`, 150ms 간격 최대 3번). `!`로 시작하는 글은 셸 모드로 바뀌므로 아예 보내지 않는다. `/`로 시작하는 글은 직접 친 것과 같이 명령으로 처리된다. 명령 전체를 입력하면 추천 목록에서 그 명령 줄이 `❯`로 선택되는데, 선택된 줄이 입력한 명령과 정확히 같을 때만 통과한다(실측: `/clear` 전송 → 새 세션). 화면을 읽지 못하면(옛 Orca, Orca가 화면 대신 지난 출력을 돌려준 `source !== 'screen'` 등) 별도 문구로 거부한다. 실측: 승인 창에 붙여 넣은 글 자체는 무시되고(숫자로 시작해도 선택 안 됨) Enter만 위험하다. 순서는 화면(글이 그려질 때까지 최대 3번) → 기록·전면 소유 → 화면 한 번 더 → Enter다. 남는 틈은 마지막 화면 확인과 Enter 사이 CLI 1회(Orca ~0.14초, tmux 수 ms)와 Claude의 다음 화면 갱신이다. 터미널에 키를 넣는 방식인 이상 이 틈은 없앨 수 없다(Claude 쪽 API가 생기면 바꿀 것). Enter 직후 기록이 `waiting`이면 "보냈는데 바로 승인 창이 떴어요"로 알린다. Orca가 Enter만 거부하면 글이 입력창에 남았다고 알려 다시 보내지 않게 한다. 보낸 직후 카드는 작업 중으로 표시하고, 작업 중인 동안 화면에 보이면 4초마다 다시 확인한다.
- **참고:** 백그라운드 서브에이전트(팀원)가 살아 있으면 Claude Code는 입력 대기 중에도 세션을 `busy`로 기록한다. 예전에는 이런 세션에 답장 버튼이 계속 안 떴다.
- **터미널 앞에 있을 때만.** Ctrl+Z로 멈춘 Claude는 기록이 `idle`로 남은 채 셸이 앞으로 나온다. 보내기 직전 `ps -o stat,pgid,tpgid`로 멈춤(`T`)이 아니고 Claude의 프로세스 그룹이 터미널 전면 그룹인지 확인한다. 그렇지 않으면 셸 명령으로 실행될 수 있어 거부한다(실측: Ctrl+Z → 거부, `fg` → 다시 보내기 가능).
- **평문만.** `\n`·`\t` 외 제어문자(ESC, BEL, C1 등)를 제거하고 trim, 1~4000자.
- Orca: `orca terminal send --terminal=… --text=<ESC>[200~…<ESC>[201~ --json`(Enter 없이) → 확인 → `orca terminal send --terminal=… --enter --json`. Orca는 `--text`를 그대로 쓰므로 bracketed paste로 감싸야 탭·줄바꿈이 글로 남는다(실측: 감싸지 않으면 탭이 키로 먹힘). `cleanInput`이 ESC를 모두 지우므로 글이 붙여넣기를 일찍 닫을 수 없다. 글과 Enter를 한 번에 보내지 않으므로 `--wait-submit`의 차례 시작 관찰은 쓰지 않는다. `--flag=값` 형식이어야 `--`로 시작하는 글도 값으로 읽힌다. `result.send.accepted`가 아니면 `refusedReason`과 함께 알리고(거부 시 CLI가 0이 아닌 코드로 끝나도 출력을 읽음).
- tmux: 고유 이름 버퍼에 **stdin으로** `load-buffer`(인수로 넘기면 끝의 `;`를 tmux가 명령 구분자로 먹음) → `paste-buffer -p -d`(bracketed paste라 줄바꿈이 조기 제출되지 않음, 실패하면 버퍼 삭제) → 150ms 후 화면을 보고, 마지막으로 기록·전면 소유를 **다시 확인**하고 `send-keys Enter`(재시도 중 Ctrl+Z로 멈춰도 Claude의 마지막 화면이 남으므로 전면 소유를 맨 뒤에 본다). 차례를 기다린 보내기는 시작할 때 세션을 다시 확인한다(앞 글이 `/clear`였으면 같은 프로세스가 새 세션으로 바뀜). 그사이 승인 화면(`waiting`)으로 바뀌었거나 화면에 입력창이 안 보이면 Enter를 누르지 않는다(작업 시작·종료는 그대로 제출). 작업 중이었으면 "대기열에 들어가 이어서 반영돼요"로 알린다.
- **한 세션에 한 번에 하나.** 업무 카드와 말풍선에서 같은 세션으로 동시에 보내면 앞 보내기가 Enter까지 끝난 뒤 다음이 시작된다(main 프로세스 안 세션별 순서). 실측: 동시에 두 번 → 첫 글 제출, 둘째는 대기열 반영.
- 결과를 확인하지 못한 실패(시간 초과 등)는 "보냈는지 확인하지 못했어요"로 알린다. 글이 이미 들어갔을 수 있어 그대로 다시 보내라고 하지 않는다.

## 이미지 첨부 (2026-10-26)

업무 카드 입력창과 말풍선 빠른 답장에서 이미지를 붙여넣기(⌘V)·끌어다 놓기·첨부 버튼으로 붙인다(PNG·JPEG·GIF·WebP, 장당 10MB, 한 번에 5장). 보내기 전 썸네일과 빼기 버튼이 보이고, 화면 내용 숨기기에서는 썸네일 대신 빈 타일만 보인다. 이미지만 보내도 된다.

- **파일은 main만 만든다.** 렌더러는 바이트만 넘기고(IPC `office:attach-image`, 신뢰한 창만) main이 앞부분 바이트(매직 넘버)로 형식을 확인해 `<userData>/attachments/<uuid>.<ext>`(폴더 0700, 파일 0600, 덮어쓰기 금지)에 쓴 뒤 **불투명 id**만 돌려준다. 보내기(`office:send`의 `images`)는 id만 싣고, main이 자기 폴더의 일반 파일(심볼릭 링크 제외)로만 풀어 경로를 얻는다. 렌더러가 경로를 지정할 길은 없다. 형식이 틀리거나 크거나, id가 이상·중복·없음이면 아무것도 입력하기 전에 거절한다. 앱을 켤 때 7일 지난 파일을 지운다(Codex 대기열은 경로만 넘기므로 에이전트가 나중에 열 수 있게 일주일 둔다).
- **어디로 가는지는 어댑터가 말한다**(`ComposerCapabilities.images`, 보내기 대상 `TerminalTarget.images`):
  - **Claude Code(Orca·tmux): `attach`.** Claude Code가 붙여넣은 이미지 파일 경로를 스스로 `[Image #N]`으로 첨부하는 동작을 쓴다. 2.1.310 번들 확인: 붙여넣기 한 번을 `/` 앞 공백과 줄바꿈으로 나눠, 조각이 `.png|.jpg|.jpeg|.gif|.webp`로 끝나는 경로면 파일을 읽어(내용도 이미지인지 확인) `[Image #N]`으로 넣고(이어지는 이미지는 공백 하나로), 나머지 글은 줄바꿈으로 이어 붙인다. 그래서 글과 경로를 한 번에 붙이면 글이 바뀔 수 있어 **두 번 나눠** 넣는다: ① 경로들을 공백으로 이어 한 번 붙여넣기 → 입력창이 정확히 `[Image #N]`×장수(또는 Claude가 읽기를 거부해 그대로 남은 경로 글)만 보일 때까지 150ms 간격 최대 20번 확인(읽고 줄이는 데 시간이 걸림) → ② 글을 붙여넣기 → Enter 직전 확인은 `promptHoldsImages`: 맨 앞이 그 장수의 `[Image #N]`(번호는 Claude 것이라 아무 수나, 같은 번호 두 번은 불가) 또는 그 경로 글이고 **그 뒤가 정확히 보낸 글**(긴 글은 기존과 같이 `[Pasted text #N …]`·보이는 끝부분)일 때만 통과. 장수가 모자라거나 남는 글이 있으면 Enter 없이 멈춘다. 마지막 이미지가 경로 글로 남았으면 글이 경로에 붙지 않게 ② 글 앞에 공백을 넣고, 확인도 그 파일 이름 바로 뒤에 공백(또는 줄바꿈)이 보여야 통과한다(이름이 줄 사이로 갈리면 확인 불가로 멈춤). 경로에 `/` 앞 공백·제어 문자가 있으면 보내지 않는다(앱 폴더 경로는 해당 없음). 이미지를 넣은 보내기가 실패해 남긴 입력창은 앱이 넣은 글로 기억하지 않는다(자리표시가 보여 글과 다름): 다시 보내면 다른 초안처럼 확인을 거친다.
  - **Codex Desktop: `attach`.** `thread-follower-start-turn`의 `input`에 앱 서버 프로토콜의 로컬 이미지 항목 `{ type: 'localImage', path }`를 글 앞에 넣는다(글이 없으면 글 항목 없음).
  - **Codex CLI 대기열: `path`.** `codex queue`는 이미지를 받지 않는다(0.163/0.164: `--image`를 주면 "`codex queue` does not support image attachments"로 끝남). 그래서 글 뒤에 빈 줄, 그다음 경로를 한 줄에 하나씩 붙여 보낸다. 입력창에 "Codex CLI에는 이미지 파일 경로로 전달돼요"라고 적는다.
  - **OpenClaw·원격 오피스·웹·데모·Orca 탭만 찾은 경우: 없음.** 첨부 버튼을 숨기고, 붙여넣거나 놓으면 이유 한 줄을 보인다. main도 이미지를 실은 원격 보내기와 이미지를 못 받는 어댑터를 거절한다.
- **초안:** 고정 카드를 닫으면 그 창이 없어지므로, 업무 카드의 첨부 목록(id와 파일 이름만)을 글 초안 옆 로컬 프로필(`office:reply-images:v1:<동료>`)에 둔다. 다시 열면(앱을 다시 켜도) 목록을 읽고 썸네일은 main에 id로 다시 받는다(IPC `office:attachment-preview`, 신뢰한 창만, 앱 폴더의 자기 이미지 파일만 — 형식을 다시 확인하고 경로는 돌려주지 않음). main에 없는 id(7일 정리 등)는 말없이 뺀다. 보내면 보낸 id만, 빼기 버튼은 그 id만 목록에서 지운다. 말풍선 빠른 답장은 열려 있는 동안만 메모리에 둔다.
- **올리는 중:** 아직 main에 넘어가는 중인 이미지 수는 입력창 단위로 창 전체에서 공유한다. 카드를 닫았다 열어도 그 수가 남아 다 올라갈 때까지 보내기가 꺼져 있다.
- **보낸 글 말풍선:** 기록에 나타날 때까지 보이는 '보냄' 말풍선은 이미지 장수도 기억한다. 기록과 맞출 때 에이전트마다 이미지가 남는 모양을 그 장수만큼만 허용한다: Claude는 글 앞의 `[Image #N]`(또는 첨부되지 않은 경로), Codex 대기열은 글 뒤의 앱 폴더 경로 줄(`…/attachments/<uuid>.<ext>`), Codex Desktop은 글 그대로. 앱 폴더 경로 하나는 정확히 `…/attachments/<uuid>.<ext>` 하나만 덮는다(기록의 줄바꿈이 공백으로 합쳐져도 두 경로가 한 장으로 세지지 않음). Codex는 글만 기록하므로 Codex Desktop에 이미지만 보낸 건 기록에 요청으로 남지 않는다: 어댑터가 `unrecorded`로 알려 '보냄' 말풍선을 만들지 않는다(알림만).
- 보안 정책: 썸네일은 `blob:` 주소라 `index.html` CSP의 `img-src`에 `blob:`를 더했다.
- 확인하지 않은 것: 실제 Claude Code·Codex Desktop 세션에 보내 보지는 않았다(키를 실제 세션에 넣지 않는 원칙). Claude는 번들 코드를 읽어 판단했고, Orca가 `draft`로 따로 알려 주는 입력창 글에도 `[Image #N]`이 그대로 들어오는지, Codex Desktop이 `localImage`를 받아 주는지는 실측 전이다.

## 입력창에 이미 글이 있을 때 (#94)

정본 `desktop/composer/`(어댑터)와 `desktop/terminals.ts`(공통 흐름), 렌더러 `src/lib/useComposerSend.ts`·`src/components/DraftConfirm.tsx`.

- **문제:** Claude Code는 답한 뒤 입력창에 다음에 칠 법한 글(prompt suggestion)을 흐리게 띄운다. 화면 글자로는 초안과 똑같아서 예전에는 "입력창에 이미 글이 있어요"로 보내기가 막혔다.
- **원칙:** 입력창 글 **전체**를 알 때만 여기서 지운다. 일부만 보이거나 알 수 없으면 아무것도 지우지 않고 "입력창 글이 다 보이지 않아 여기서 지울 수 없어요. 터미널에서 비운 뒤 다시 보내 주세요"로 안내하고, 터미널로 이동할 수 있으면 [터미널로 이동]을 준다.
- **구분과 빈 입력창:** tmux는 `capture-pane -p -e`로 글자의 흐림(SGR 2)을 읽는다. 흐린 글만 있으면 추천 글(또는 예시 안내)이라 그대로 보낸다. 흐리지 않은 글은 `Try "…"`처럼 보여도 직접 친 초안이다. **빈 입력창은 정확히 한 줄이 비었을 때**(tmux는 흐린 글만 있는 경우 포함, Orca는 `draft`가 없거나 비고 입력창 줄이 비었거나 예시 안내일 때)뿐이다. 빈 줄이 여러 개인 입력창은 줄바꿈을 친 초안이다(위로 스크롤된 글이 숨어 있을 수 있음). Orca는 글자만 주고, 1.4.216부터는 입력창 글을 화면(`tail`)에서 빼 `draft`로 따로 준다(추천 글도 `draft`에 들어옴, 실측). 그래서 Orca에서는 추천 글을 구분할 수 없다(`canDetectSuggestion: false`). 초안이나 구분할 수 없는 글이면 **아무것도 입력하지 않고** `{ status: 'needs-confirm', draft, agent, maybeSuggestion?, clearable? }`를 돌려준다(`clearable: false`면 여기서 지울 수 없음).
- **전체를 아는 경우(`whole`):**
  - **tmux:** 입력창 줄 수가 그 패널 높이에서 Claude Code가 보여 주는 최대 줄 수보다 **적을 때**. 최대 줄 수는 max(3, ⌊(패널 높이 − 10) / 2⌋)다(아래 측정). 입력창이 최대 줄 수에 닿으면 앞부분이 스크롤돼 숨어 있을 수 있고, 그런 표시가 화면에 없어 알 수 없으므로 지우지 않는다. 패널 높이와 대체 화면 여부는 `display-message '#{pane_in_mode} #{pane_height} #{alternate_on} #{alternate-screen}'`로 화면과 함께 읽는다. 최대 줄 수는 Claude Code의 **전체 화면 렌더러**(대체 화면)에만 있다(2.1.309 코드: `maxVisibleLines`는 fullscreen일 때만 넘기고, 창은 커서 줄 가운데 기준으로 잘림 — 커서가 끝이 아니면 아래 줄도 숨음). 기본(inline) 렌더러는 일반 화면에 상자를 전부 그리므로, `alternate_on`이 0이면 두 가로줄이 다 보이는 상자는 줄 수와 무관하게 전체로 본다. 단 패널의 `alternate-screen` 옵션이 꺼져 있으면 tmux가 전체 화면 렌더러도 일반 화면에 그려 `alternate_on`이 늘 0이므로, 이 옵션이 켜져 있을 때(`#{alternate-screen}`=1)만 믿고 그 밖에는(꺼짐·읽지 못함) 줄 수 기준을 그대로 쓴다.
  - **Orca(`draft` 있음):** `draft`는 입력창에 **보이는 만큼만** 들어오고(측정) 패널 높이는 알 수 없으므로, 어떤 입력창에도 다 들어가는 짧은 글(가장 넓게 셈: 아스키 외 글자는 두 칸, 줄바꿈 여유를 두고 2줄 이하)만 전체로 본다.
  - **예전 Orca(`draft` 없음):** 입력창 글이 화면에 그려질 뿐이라 추천 글과도 구분되지 않는다. 여기서 지우지 않는다.
  - **어디서든 전체가 아닌 것으로 보는 경우:** 글에 `[Pasted text #N …]`·`[Image #N]` 자리표시가 있을 때(화면에 없는 내용을 대신함), 패널 높이가 12 미만일 때(입력창 아래 테두리가 잘림, 측정), 작업 목록(ctrl+t)이 보일 때(아래 안내 `ctrl+t to hide tasks`나 입력창 위 `☐`·`◼`·`✔` 줄; 이 상태의 최대 줄 수는 도구 실행 없이 띄울 수 없어 재지 않았으므로 안전하게 막음).
- **Orca `draft` 읽기(기존 문제도 함께 수정):** Orca가 입력창 글을 `draft`로 옮긴 뒤로는 화면의 입력창이 늘 `❯`만 보여, 예전 코드는 초안이 있어도 빈 입력창으로 보고 그 뒤에 이어 입력했고, 넣은 글도 화면에서 확인하지 못해 제출하지 못했다. 이제 `draft`가 있으면 그것을 입력창 글로 읽는다(`Screen.composer`). `draft`에 든 글은 예시 안내처럼 보여도 초안으로 본다(예시 안내는 화면에 남고 `draft`에는 들어가지 않음).
- **확인 UI(한 벌):** 업무 카드 입력창과 말풍선 빠른 답장이 같은 `DraftConfirm`을 쓴다. "Claude 입력창에 이 글이 있어요" + 그 글 미리보기 + [지우고 보내기]·[취소](전체를 모르면 안내 문구 + [터미널로 이동]·[취소]). 에이전트 이름은 어댑터(`agent`)에서 온다. 쓰던 답장은 그대로 남고, 취소와 Esc(두 곳 모두)는 질문만 닫는다. 이어 붙여 보내기는 없다(지시가 섞일 위험). 추천 글과 구분할 수 없는 화면(Orca)에서는 "추천 글일 수도 있어요 … 지우면 이 글이 클립보드에 들어가 원래 클립보드 내용을 대신해요"를 덧붙인다. 화면 숨기기 모드에서는 미리보기 글을 가린다. 대상이 입력을 받지 않는 상태(승인 대기 등)면 [지우고 보내기]가 잠긴다. 포커스는 옮기지 않아 Enter 연타가 지우기로 이어지지 않고, 영역은 `role="status"` 하나로 제목을 한 번만 읽는다. 데스크 펫·책상 줄·바닥 책상 창은 답장 칸 바로 아래에서 창이 끝나므로 질문을 답장 칸 **위**에 띄우고, 큰 사무실에서는 답장이 열린 프로젝트 구역을 다른 구역보다 위에 둔다.
- **지우고 보내기:** `send(id, text, { replaceDraft: <보여 준 글> })`. main이 화면을 다시 읽어 입력창 글이 보여 준 것과 같을 때만(그려진 모양 기준) 진행하고, 다르면 새 글로 다시 묻는다(`changed`). 전체를 모르면 지우지 않는다. 순서는 **입력창 글 전체를 클립보드에(main `clipboard.writeText`, 첫 키 전에 한 번) → Ctrl+K·Ctrl+U 한 쌍씩 누르며 매번 확인 → 빈 입력창 확인 → 입력 → 입력창 확인 → 기록·전면 소유 → 화면 한 번 더 → Enter**다.
- **비우기(Claude Code):** **매 쌍을 누르기 전에** Claude 기록(같은 pid, 입력을 받는 상태)과 터미널 전면 소유(`ownsTerminal`)를 다시 확인하고, 아니면(Ctrl+Z 등) 바로 멈춘다("입력창을 비우는 사이 Claude 상태가 바뀌어 멈췄고 보내지 않았어요" + 클립보드 안내). 한 쌍은 커서가 있는 줄(또는 그 옆 줄바꿈)을 지운다(커서가 끝이면 n줄에 2n−1쌍). 매 쌍 뒤 입력창은 **확인한 글에서 한 구간만 빠진 모양**(그려진 모양, 글자 단위)이어야 한다 — 커서가 가운데 줄에 있어도 성립한다. 그 밖의 모양(글이 늘거나 두 군데가 빠짐)은 누가 입력한 것으로 보고 멈춰 다시 묻는다. 새로 보인 글이 전체가 아닐 수 있으면(자리표시, 최대 줄 수) 확인 없이 바로 멈추고 "여기서 지울 수 없어요"로 다시 묻는다. 빈 줄뿐인 초안은 클립보드에 넣지 않고 지운다(성공 알림에도 클립보드 안내를 붙이지 않음). 같은 글이 키에 두 번 연속 그대로면, 한 번도 줄지 않았으면 키가 닿지 않은 것일 수 있어 실패로, 줄던 중이면 빈 줄이 남은 것일 수 있어 몇 번 더 눌러 본 뒤 실패로 처리한다. 120ms 간격, 최대 max(60, 2×줄 수+20)쌍(400쌍 상한 — inline 렌더러에서는 패널 높이만큼 긴 초안도 전체로 보므로). tmux는 `send-keys C-k C-u`, Orca는 같은 바이트(`\x0b\x15`)를 `--text=`로 보낸다. Esc는 쓰지 않는다(작업 중이면 턴을 끊고, 빈 입력창에서 두 번이면 되돌리기 메뉴).
- **추천 글이 돌아올 때:** 입력창이 비면 같은 추천 글이 다시 뜬다. tmux에서는 흐리게 보여 빈 입력창으로 확인된다. Orca에서는 `draft`에 들어오므로, 초안이 없어진 뒤 **초안의 일부가 아닌** 글이 나타나면 먼저 클립보드에 덧붙이고(초안 + 그 글) 두 쌍 더 눌러 봐서 그대로면 추천 글로 **추정**한다. 그 사이 줄거나 사라지면 입력이었던 것으로 보고 멈춰 다시 묻는다(이미 클립보드에 있음, 보내지 않음). 전체를 알 수 없는 글은 이렇게 시험하지 않는다. 이 두 번째 복사가 실패하면 "초안은 지워서 클립보드에 있지만, 그 뒤에 나타난 글을 복사하지 못해 더 지우거나 보내지 않았어요"로 알린다. 처음부터 추천 글만 있는 입력창은 줄지 않으므로 여기서 비우지 못한다("추천 글이면 여기서는 지울 수 없어요. 터미널에서 그 위에 입력해 주세요").
- **두 쌍에도 전혀 줄지 않은 글(tmux·Orca 공통):** 키가 닿지 않았거나, 키가 건드리지 못하는 추천 글이다. tmux에서도 추천 글의 글자 하나라도 흐리지 않게 그려지면(색으로만 회색, 커서 칸 반전 등) 초안으로 읽힌다(2026-10-21 제보: tmux에서 한글 추천 글 `ㄱㄱ  머지하고  앱  띄워줘`가 초안으로 보이고 "Claude 입력창을 비우지 못해"로 끝남, Orca는 정상). 그래서 두 호스트 모두 확인 글자 `l`을 하나 쳐 본다. 입력창이 `l`만 남으면 추천 글이었으므로 BSpace로 지우고 추천 글로 **추정**한다(넣은 글은 정확히 같은 글만 인정). 글 사이에 `l`이 끼면 지우기만 안 되는 키 모드라 되돌리고 실패, 그대로면 실패다.
- **비운 뒤 한 쌍 더(tmux, 일부 가려진 입력창은 Orca도):** 입력창이 비어 보이면 Ctrl+K·Ctrl+U를 한 번 더 누르고 다시 읽는다. 빈 줄에서 이 쌍은 글자를 지우지 않고(Ctrl+K는 다음 줄을, Ctrl+U는 앞 줄바꿈을 붙임) 가려져 있던 줄을 화면으로 끌어온다. 그대로 비어 있어야 비운 것으로 본다. 새 글이 나타나면 한 번도 보여 주지 않은 글이므로 멈추고 **일부만 보이는 글**로 다시 묻는다. 일부 교체를 허락받은 경우에도, 앞서 보고 백업한 줄로만 이뤄진 글이 아니면 그사이 사람이 친 글일 수 있어(허락은 처음 초안의 가려진 부분까지만) 백업에 더한 뒤 지우지 않고 다시 묻는다 — 빈 화면 뒤 한 줄씩 드러나는 상자라면 확인할 때마다 한 덩이씩 지워진다(2026-10-23 제보: 긴 초안의 일부 교체 뒤 "넣은 글만 있는지 확인하지 못해"와 "그사이 입력창 글이 바뀌었어요"가 번갈아 뜸 — 스크롤된 상자가 빈 한 줄만 보이는 사이 위쪽 줄이 남았다고 보고 막음, 실측 확인은 못 함).
- **앱이 넣고 제출하지 못한 글:** 글이 패널에 닿을 수 있게 된 순간(tmux `load-buffer` 성공 뒤 `paste-buffer` 직전, Orca `send` 직전) 세션별로(10분) 기억하고(그 전에 실패하면 아무것도 넣지 않았으므로 기억하지 않음. Orca가 `accepted: false`로 분명히 거절하면 잊고, 응답이 없거나 불분명한 실패는 들어갔을 수 있어 기억을 유지) Enter가 성공하면 지운다. 다음 보내기·실패 뒤 읽기에서 입력창이 그 글과 **정확히 같고 전체가 보이면**(공백·빈 줄까지, 상자의 자동 줄바꿈만 무시) 사람의 초안으로 묻지 않는다. 한 번이라도 그렇지 않게 보이면(비었음·다른 글·고친 글·일부만 보임·못 읽음) 기억을 바로 버린다 — 사람이 보냈거나 지운 뒤 같은 말을 다시 쳐도 그건 사람의 글이다. 묻지 않고 지우는 것은 **같은 글을 다시 보낼 때만**이다: 지우는 글과 넣는 글이 같아 무엇도 잃지 않는다. 다른 글을 보내면 남은 글은 보통 초안처럼 묻는다. 읽기 복구(`inspectTerminalDraft`)는 null(오류 문구만 표시), 다음 보내기는 묻지 않고 클립보드도 건드리지 않은 채 같은 비우기 경로로 지운 뒤 새로 넣고 확인한다. 조금이라도 다르면(터미널에서 고침, 가려진 줄이 있음) 보통 초안처럼 묻는다.
- **넣은 글 확인:** 빈 입력창을 **직접 확인한** 경우(tmux에서 비었거나 흐린 추천 글만 남음, Orca에서 `draft`가 빔)에는 보통 보내기처럼 긴 글의 자리표시(입력창 전체가 `[Pasted text #N …]` 하나)와 끝부분(40자 이상) 일치를 인정한다. Orca에서 추천 글을 **추정**한 경우에만 정확히 같은 글만 인정하고, 아니면 Enter를 누르지 않고 "비운 입력창에 넣었지만 넣은 글만 있는지 확인하지 못해 제출하지 않았어요"로 알린다(글은 입력창에 남는다).
- **클립보드:** 세션마다 마지막 백업을 메모리에 기억한다(10분, 보내기 성공 시 바로 지움). 보내기마다 그 값을 한 번 읽어 두고(`base`), 새 백업은 `base`와 이번 초안 전체를 합친 것(한쪽이 다른 쪽을 줄 단위로 포함하면 큰 쪽, 아니면 이전 다음 이번)이다 — 그래서 지우다 멈춰 다시 확인해도 앞서 지운 글이 사라지지 않고, 반복해도 늘어나지 않는다. 기억한 글은 **지금 클립보드가 그 글일 때만** 쓴다: 사용자가 다른 것을 복사했으면 잊고, "지금까지 지운 글은 클립보드에 있어요" 안내도 내지 않는다(main이 `clipboard.readText()`로 확인). 복사가 실패하면 지우지 않는다. 클립보드에 무언가 넣은 뒤의 실패 문구에는 "입력창에 있던 글은 클립보드에 있어요"가 붙는다(복사 실패 문구에는 붙이지 않음). 성공하면 알림에 "지운 글은 클립보드에 있어요"를 붙인다.
- **백업은 화면에서 다시 만든 글이다:** 미리보기와 클립보드 글은 화면(또는 Orca `draft`)에서 읽은 것이라 줄바꿈 위치·공백이 원래와 다를 수 있고, 긴 붙여넣기는 `[Pasted text #N …]` 자리표시만 들어간다. 원래 글 그대로는 지운 직후 그 터미널에서 Ctrl+Y로 되살릴 수 있다(실측).
- **어댑터(에이전트별 차이는 여기만):** `ComposerAdapter { agent, capabilities(host), inspect(host), clear(host, from, backup) }`, 상태 `empty | suggestion | draft | unknown | closed | unreadable | unsupported`(`draft`·`unknown`은 `whole`을 가짐), 비우기 결과 `cleared | failed(partial?) | changed`. 능력은 전달 방식(`delivery: 'terminal' | 'queue' | 'none'`)과 입력창 능력(`canInspect`·`canDetectSuggestion`·`canClear`)으로 나뉜다. 호스트(tmux·Orca)는 `ComposerHost { styled, read, press, wait }`로 화면 읽기와 키 입력만 제공한다.
  - `clear(host, from, backup, proceed)`: `proceed`는 매 키 전에 묻는 확인(공통 흐름이 Claude 기록·전면 소유를 넘김)이다.
  - **Claude Code** (`claude-code.ts`): `delivery: 'terminal'`, `canInspect`·`canClear`, `canDetectSuggestion`은 tmux만. 입력창 해석(`readPrompt`·`promptHolds`·`classifyPrompt`·`maxBoxRows`)도 여기 있다.
  - **Codex** (`index.ts`의 `codexQueueComposer`): `delivery: 'queue'` — `codex queue`로 보내 TUI 입력창을 건드리지 않는다. main이 이 능력을 보고 대기열로 보낸다. 터미널 입력 흐름(`sendToTerminal`)은 `delivery: 'terminal'`이고 입력창을 읽을 수 있는 어댑터만 받는다.
  - **그 밖(OpenClaw 등)**: `delivery: 'none'` → "여기서 보낼 수 없어요"로 거부.
- **[터미널로 이동]:** 업무 카드·큰 사무실·책상 줄·펫 모두 책상 도구의 이동과 같은 `jumpOrCopy`를 쓰고 결과를 알림으로 보여 준다. 터미널이 사라져 재개 명령을 클립보드에 복사하게 되면 "복사했어요" 알림이 떠, 클립보드에 있던 백업이 바뀐 것을 알 수 있다.

### 측정 (Claude Code 2.1.296, tmux 3.6a, Orca 1.4.216, 2026-10-12)

임시 tmux 서버(전용 소켓)와 Orca 임시 터미널 탭에 빈 프로젝트로 `claude`를 띄워 `capture-pane -p`·`-p -e`·`display-message '#{cursor_x},#{cursor_y}'`, `orca terminal read --screen --json`으로 읽었다. 도구 사용은 승인하지 않았고 프롬프트는 "한 문장으로 답해" 수준만 썼다. 끝난 뒤 tmux 서버와 Orca 탭을 닫았다.

| 상태 (120×40)          | `-e`로 본 입력창 줄                                                        | 커서                |
| ---------------------- | -------------------------------------------------------------------------- | ------------------- |
| 빈 입력창(예시 안내)   | `❯\xa0` + `ESC[2m`Try "…"`ESC[0m`                                          | 2,36 (`❯ ` 바로 뒤) |
| 추천 글                | `❯\xa0` + `ESC[2m`<추천 글>`ESC[0m`                                        | 2,36                |
| 한 줄 초안(입력)       | `❯\xa0hello draft` (속성 없음)                                             | 13,36 (글 끝)       |
| 여러 줄 초안(붙여넣기) | `❯\xa0first line` / `  second line` / `  third line`                       | 12,36               |
| 긴 붙여넣기            | `❯\xa0note: [Pasted text #1 +12 lines] tail`, 아래 `paste again to expand` | 39,36               |
| 작업 중 초안           | `ESC[38;5;246m❯\xa0ESC[39mdraft while busy` (표식만 회색)                  | 18,36               |

- `-p`(글자만)로는 추천 글과 초안이 똑같다. 표식 뒤 공백은 NBSP(`\xa0`). 속성은 바뀌는 곳에만 찍혀 줄을 넘어 이어진다(`ESC[0m`이 다음 줄 맨 앞에 오기도 함). 색(`38;5;n`)은 상태마다 달라 기준으로 쓰지 않는다.
- **추천 글이 뜨는 조건:** 대화에 어시스턴트 답이 2개 이상, 터미널 포커스가 있어야 한다(내부 사유 `early_conversation`·`unfocused`). 포커스 보고가 없는 tmux(`focus-events off`, 클라이언트 없음)에서는 안 뜨고, 포커스 입력(`ESC[I`)을 넣은 뒤 다음 답에서 떴다. Orca 탭에서는 두 번째 답 뒤에 바로 떴다. 계정 플래그 또는 `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=1`, 설정 `promptSuggestionEnabled`로 켜진다.
- **입력·붙여넣기는 추천 글을 대신한다:** 첫 글자부터 추천 글이 사라지고(남은 부분을 흐리게 이어 보여 주지 않음) 입력한 글만 남는다. 입력창을 다시 비우면 같은 추천 글이 돌아온다. 지우기 키는 추천 글에 아무 영향이 없다(tmux·Orca 모두).
- **비우기 키:** Ctrl+U는 커서 앞(줄 처음까지)을, Ctrl+K는 커서 뒤를 지운다. 줄 처음에서 Ctrl+U, 빈 줄에서 Ctrl+K는 줄바꿈을 지워 줄을 합친다(커서가 끝일 때 3줄 초안은 Ctrl+U 5번, 즉 2n−1). 커서가 가운데여도 C-k C-u 쌍을 반복하면 비워진다. 붙여넣기 자리표시는 한 쌍으로 지워진다. 빈 입력창에 더 눌러도 변화 없음. 지우면 입력창 위에 `Ctrl+Y to paste deleted text`가 잠깐 뜨고, Ctrl+Y는 마지막에 지운 글(붙여넣기 자리표시 포함)을 되살린다. 작업 중에도 같다.
- **입력창 최대 줄 수(tmux):** 아주 긴 글을 직접 입력해 입력창 줄 수를 셌다. 높이 12·14·15·16 → 3줄, 20·21 → 5, 25 → 7, 30 → 10, 33 → 11, 40 → 15, 50 → 20, 70 → 30(폭 40·80·120 모두 같음). 즉 max(3, ⌊(높이 − 10) / 2⌋). 넘치면 **끝부분만** 보이고(맨 윗줄도 `❯`로 시작) 잘렸다는 표시는 없다. (이 측정은 전체 화면 렌더러에서 한 것이다. 2.1.309 코드에서 공식은 `max(3, ⌊rows/2⌋ − 5)`로 같고, 기본 렌더러에는 상한이 없다.)
- **작은 패널·대기열(tmux):** 높이 8~11에서는 입력창 아래 테두리와 안내 줄이 화면 밖으로 잘려 입력창 자체를 읽지 못한다(높이 12부터 입력창 3줄). 작업 중 대기열 메시지(`❯ queued …` + `ctrl+x ctrl+s to send now`)와 진행 표시가 보일 때도 높이 30에서 최대 10줄로 공식과 같았다. 작업 목록(ctrl+t)은 도구를 실행해야 생겨 재지 않았다.
- **긴 붙여넣기(tmux):** **4줄 이상이거나 800자를 넘으면** `[Pasted text #N +k lines]`(줄이 하나면 `[Pasted text #N]`)로 접힌다(3줄·799자는 그대로).
- **Orca:** `orca terminal send --text=$'\x0b\x15'`가 tmux와 똑같이 지운다(3줄 초안 → 한 쌍 뒤 2줄 → …, 추천 글은 그대로, 붙여넣기 자리표시는 한 쌍). 1.4.216은 입력창 글을 `tail`에서 빼고 `draft` 필드로 준다(`"draft is UI-only composer text excluded from tail"`): 빈 입력창은 `draft` 없이 `tail`에 예시 안내, 초안·붙여넣기 자리표시·**추천 글**은 `draft`에, 입력창 줄은 `❯`만. 2,499자 문단을 입력하자 `draft`에는 보이는 끝부분 1,694자만 들어왔다 — `draft`도 입력창에 보이는 만큼이다. `terminal read`·`terminal show`는 패널 높이를 주지 않고, `tail`은 빈 줄을 뺀다.
- **실제 비우기 확인:** 이 어댑터로 실제 Claude Code 입력창을 비웠다. 40×16(최대 3줄): 한 줄·이모지/키릴 문자·한글 두 줄·접힌 붙여넣기는 첫 키 전 백업 1번으로 빈 입력창이 됐고, 3줄 초안과 긴 문단은 최대 줄 수에 닿아 아무것도 누르지 않고 거부했다. 120×40(최대 15줄): 3줄·긴 문단(약 900자)까지 모두 비워졌고 백업은 원래 글과 같았다.
- **Codex:** `codex queue`는 입력창을 거치지 않으므로(위 Codex 절) TUI는 따로 측정하지 않았다.

## 질문·플랜·권한 확인에 답하기 (#127)

정본 `desktop/prompts/`(에이전트별 어댑터: `claude-code.ts` 화면·키, `claude-target.ts` 세션·기록), `desktop/answers.ts`(공통 흐름), `desktop/main.ts`(IPC·설정·확인창), 렌더러 `src/components/RequestCard.tsx`·`src/lib/usePrompt.ts`. 수집 쪽은 `server/adapters/requests.ts`.

**원칙: 화면이 기준이다.** 화면의 대화상자가 무엇을 묻는지 모호하지 않을 때만 키를 누른다. 확실하지 않으면 키를 누르지 않는다.

### 보여 주기 (모든 세션)

- **수집:** 답이 아직 없는 입력 요청 이벤트에 선택 필드 `request`를 붙인다(이벤트 id·소식 버전은 그대로). `question`(AskUserQuestion·Codex `request_user_input`의 `questions[{header?, question, multiSelect, options[{label, description?}]}]`, Codex의 문자열 선택지·`title`도 읽음), `plan`(ExitPlanMode `plan` 마크다운 2만 자, `planFilePath`). 모두 `redactStrict()`(이벤트 글보다 넓게 가림) 후 길이 제한하고, 제한에 걸려 잘린 요청은 `truncated`로 표시한다(보여 주기만, 앱에서 답하지 않음). 정본 그대로 저장하고 읽을 때 자리표시만 현지화한다. 답이 기록된 요청은 아무것도 남기지 않는다.
- **권한 확인은 저장하지 않는다:** 다른 도구의 입력(명령·파일·주소·MCP 인수)은 수집기가 저장하지 않는다. 화면에서 읽은 명령·경로·주소는 main에서 원문 그대로 비교하고, 렌더러에는 `redactStrict()`로 비밀을 가린 사본만 보낸다(`--token=abc123` → `--token=[숨김]`). 실행 기록이 `waiting`일 때 `applyLiveWait`가 결과 없는 마지막 호출을 `request-input`으로 바꿀 뿐이고, 렌더러는 그 호출의 **도구 이름만**으로 권한 요청을 만든다(`openRequest`). 무엇을 실행하려는지는 데스크탑 앱이 그때그때 **화면에서** 읽어 카드에 보여 준다(`PromptView.subject`). 메모리에서만 쓰고 저장하지 않는다.
- **카드:** 업무 카드(큰 사무실 오른쪽 칸·팝업 카드 공통)의 아래 입력창 위, 호출 중일 때 `RequestCard` 한 벌(길면 그 안에서 스크롤). 질문(머리표·복수 선택 표시·선택지 설명), 플랜(접기/펼치기, 마크다운), 권한(도구 이름, 그리고 화면에서 읽은 명령·파일·주소). 화면 숨기기에서는 그리지 않는다. 터미널 이동은 카드 아래의 이동 버튼을 그대로 쓴다. 묻는 내용이 없을 때만 그 옆에 '답변과 승인은 원래 앱에서' 안내가 붙는다.
- **말풍선:** 첫 질문의 첫 줄(여럿이면 "외 N개"), "플랜 승인", "Bash 허락할까요?"(라벨 '응답 필요'). 소식 글과 버전은 바꾸지 않고 읽을 때만 바꾼다.

### 답하기 (Claude Code · Orca/tmux, 데스크탑)

- **설정 두 개, 세 상태:** `questions`(질문·플랜 승인)와 `permissions`(권한 확인). 각각 `unset`(아직 묻지 않음) / `on` / `off`(명시적으로 끔). Electron `userData/answer-prompts.json`(0600)에만 저장하고 IPC `office:answer-settings`로만 읽고 바꾼다. 파일이 없으면 `unset`, 읽을 수 없거나 깨졌으면 `off`(출시 전 빌드가 쓴 `true`/`false`는 `on`/`off`로 읽음). `unset`이면 처음 답할 때 main이 종류별 **네이티브 확인창**을 띄우고, 승낙하면 `on`으로 저장한 뒤 **열린 요청을 다시 읽어 같은 이벤트·같은 `tool_use` id일 때만** 이어서 보낸다. `off`면 버튼 없이 이유와 [터미널로 이동]만 보인다(설정에서 켜야 함). 설정 쓰기(설정 화면과 첫 답 모두)는 한 줄로 차례대로 실행하고, 매번 파일을 다시 읽어 바꾼 칸만 합친다.
- **한 번짜리 선택지만:** 권한은 화면의 `Yes`(한 번 허락)와 `No`(Fetch는 `No, and tell Claude what to do differently (esc)` — 측정상 그냥 거절), 플랜은 `Yes, manually approve edits`만 버튼이 된다. '항상 허락'·'다시 묻지 않기'·'auto mode로 바꾸기'·'편집 자동 허락'·bypass, 그 밖에 모르는 `Yes, …`는 계속 적용되는 선택지로 보고 버튼으로 내지 않는다("터미널에서 골라 주세요"). 글을 받는 줄(플랜 수정 요청, Tab으로 바뀐 Yes/No)도 내지 않는다. 질문의 'Type something' 줄은 단일 선택 질문에서만 질문별로 "직접 입력"으로 받는다(복수 선택은 없음).
- **어느 호출인지(`identify`):** 어댑터가 세션의 기록에서 **현재 차례에 결과가 없는 호출 전부**(사이드체인 제외, 줄 단위 JSON 파싱)를 읽고, 화면이 그중 **정확히 하나**와 같을 때만 답한다. 둘 이상이 같으면(같은 명령을 동시에 둘) 답하지 않는다. 질문·플랜은 그 호출이 카드 이벤트의 `tool_use` id여야 한다. 권한 확인은 한 차례에 호출이 여럿이면 Claude Code가 **첫** 호출을 묻는데 실행 기록 overlay는 **마지막** 호출을 표시하므로, 화면과 맞는 그 열린 호출을 대상으로 삼는다. 대신 카드에 보여 준 호출 id(`PromptView.callId`)를 답(`AnswerChoice.callId`)에 실어 보내고, 답할 때 화면의 호출이 그 id와 다르면(그사이 다른 확인으로 바뀜) 키를 누르지 않는다. 카드의 제목·명령은 언제나 그 화면의 호출에서 온다(`PromptView.tool`·`subject`): 기록이 다른 도구(예: Bash 다음 Write)를 표시해도 버튼이 답하는 호출과 다른 이름은 보이지 않는다. 한 호출에 답하면 카드는 그 호출 id만 '보냈어요'로 두고 계속 화면을 읽어, 다음 호출이 뜨면 그 제목과 버튼을 다시 보여 준다(같은 호출에는 두 번 보내지 않음). 실측(tmux): 한 메시지의 병렬 Bash + Write에서 Claude Code는 첫 호출에 답하기 전까지 두 호출을 기록에 쓰지 않아, **첫 확인은 '답할 요청이 없어요'로 터미널에서 답해야** 하고, 그 뒤의 Write 확인은 카드에서 'Create file · batch-b.txt'로 답해졌다.
  - 질문: 화면의 질문 글·선택지 글(순서까지)·복수 선택 여부·머리표가 그 호출의 입력과 같다(공백·마크다운 기호 무시). 잘린 요청은 비교하지 않는다.
  - 플랜: 화면 아래의 플랜 파일 이름이 `planFilePath`와 같고(둘 다 있을 때), **화면에 보이는 플랜 전체**가 기록의 플랜 앞부분과 같다(마크다운 기호·글머리 기호·공백 무시). 그사이 고친 플랜(ctrl+g)은 같지 않다.
  - 권한: 제목으로 도구를 정하고(`Bash command`↔Bash, `Create file`↔Write, `Edit file`↔Edit·MultiEdit, `Fetch`↔WebFetch — 측정한 제목만), 화면에서 읽은 것을 **그대로** 비교한다. Bash는 `╌` 칸 안의 명령(줄바꿈된 줄은 칸 폭을 채웠으면 붙여서 다시 잇고, 흐린 `│ ` 테두리 제거)을 공백만 정규화해 **완전히 같아야** 한다(셸 기호는 하나도 무시하지 않음: 접두·부분 문자열·`>`↔`|`·`~`↔`/` 모두 다름). 파일은 제목 다음 줄의 경로가 입력 경로 그대로이거나 그 호출의 작업 폴더 기준 상대 경로이거나 `~/…`여야 한다(파일 이름만 같으면 아님). Fetch는 `url:` 줄과 입력 URL이 URL 표준형으로 같아야 한다. 그 밖의 제목(MCP 도구, 노트북 등)은 답하지 않는다. 훅이 명령을 바꾼 경우(`git push` → `rtk git push`)·서브에이전트의 확인(부모 기록에는 Agent 호출뿐)은 같지 않아 답하지 않는다.
- **공통 흐름(`answerRequest`, 에이전트를 모름):** 어댑터의 `target`(세션의 터미널·기록)으로 대기 중·같은 프로세스·터미널 전면 소유 → 화면(읽지 못하면 세 번 더) → `identify`가 그 호출 하나 → 어댑터가 키를 누른다. 어댑터는 **매 키 전에** 실행 기록·전면 소유를 다시 묻고 화면이 여전히 그 호출을 묻는지 확인하며, **매 키 뒤에** 화면을 다시 읽어(최대 4번, 120ms 간격) 그 키가 한 일을 확인한다. 화살표는 **한 번에 하나씩** 누른다. Enter는 마지막에 기록·전면·화면을 한 번 더 본 뒤에만 혼자 누른다. 뒤이어 대화상자가 사라졌는지 본다 — 화면을 읽지 못한 것은 닫힌 것이 아니므로 다시 읽고, 끝내 못 읽으면 "보냈지만 확인하지 못했어요"로 알린다. 그다음 기록에 **그 `tool_use` id의 `tool_result`**(줄 단위 파싱, 부분 문자열 아님)가 생겼는지 최대 3초 본다. 없으면(허락한 명령이 아직 실행 중 등) "보냈지만 기록에 아직 답이 보이지 않아요"로 솔직히 알린다. 한 세션에 한 번에 하나만 답한다. 이미 키를 눌렀으면 실패 문구에 "터미널을 확인해 주세요"를 붙인다.
- **키 순서(어댑터):**
  - 키를 누르기 전: 질문 글이 서로 같거나 한 질문 안에 선택지 글이 같으면, 또는 검토 화면이 창에 다 들어가지 않을 만큼 창이 낮으면(tmux 높이 < 14 + 질문 수×2) 답하지 않는다. 터미널에서 이미 고르던 답(체크된 줄, 답한 탭, 입력된 글, 첫 질문이 아님)이 있어도 손대지 않는다.
  - 질문(하나·단일 선택): ↓/↑로 한 칸씩 그 줄까지 → Enter. 이후 화면 전환을 읽는다. 바로 닫히는 버전은 추가 Enter 없이 끝내고, 검토 화면이 열리는 버전은 원래 질문과 고른 답을 모두 검증한 뒤 `Submit answer` 또는 `Submit answers`에서 최종 Enter를 누른다. 빈 화면·이전 화면이 잠깐 남는 전환도 재확인한다(#151).
  - 직접 입력: 'Type something' 줄로 → 붙여넣기 직전에 화면을 다시 읽어 커서가 그 빈 줄에 있는지 확인 → 글(한 줄로 정리, 2000자)을 bracketed paste(tmux `paste-buffer -p`, Orca `ESC[200~…ESC[201~`) → 줄이 정확히 그 글인지 확인 → Enter.
  - 복수 선택: 고를 줄과 지금 체크가 다른 줄마다 이동 → Space → 체크 확인. 끝나면 →(다음 질문이나 검토 화면).
  - 질문 여럿: 질문마다 위 순서 → 검토 화면에서 모든 질문의 답이 고른 것과 같고(질문마다 한 번씩) 경고가 없는지 확인 → "Submit answers"에서 Enter. 단일 질문의 직접 입력에도 검토 화면이 열리면 같은 검증을 적용한다. 알 수 없는 확인 화면은 닫힘으로 처리하지 않는다. 줄바꿈이 있거나 80칸보다 넓은 질문(한글 약 40자)은 질문 화면과 검토 화면 모두 왼쪽 세로줄(` │ ● 질문…`) 안에 그려지므로(2.1.304 `needsGutter`) 세로줄을 걷어 내고 읽는다. 복수 선택 답은 `, `로 잇고 `, `나 `"`가 든 선택지는 JSON 따옴표로 감싼다.
  - 플랜·권한: 사람이 본 번호와 **글**이 화면의 그 줄과 같고 한 번짜리 선택지여야 한다 → 그 줄까지 한 칸씩 → Enter.
  - **누르지 않는 키:** 숫자(누르는 순간 고르고 제출), Tab(권한의 Yes/No를 글 입력 줄로 바꿈), Esc(도구 호출 전체 취소), Ctrl+C/D/Z, ←. "Chat about this"·"Cancel"·빈 글 줄의 Enter는 도구 호출을 거절하므로 고르지 않는다. 테스트로 고정했다.
- **호스트 키:** tmux는 `send-keys`의 `Up`·`Down`·`Right`·`Space`·`Enter`. Orca는 같은 바이트(`ESC[A`·`ESC[B`·`ESC[C`·공백)를 `--text=`로, Enter는 `--enter`로 보낸다(Orca가 ESC 시퀀스를 그대로 쓰는 것을 `od -c`로 확인).
- **호스트별 지원:** 세 종류(질문·플랜·권한) 모두 tmux와 Orca 실제 탭에서 처음부터 끝까지 답해 확인했다(아래). 어댑터의 `answers(host)`가 측정한 종류만 허용한다.
- **경계:** Codex·OpenClaw는 보여 주기만 한다(어댑터 `unsupported`: Codex TUI의 승인·질문에 바깥에서 답하는 공개 경로가 없고, `codex queue`는 메시지만 더한다). 웹 미리보기는 답할 수 없다(IPC가 main에만 있음, 테스트로 고정). Claude Code의 백그라운드 팀원이 살아 있어 기록이 `busy`로 남는 동안은 `waiting`이 아니라서 답하지 않는다.

## 경계

- IPC `office:terminals`·`office:jump`·`office:send`·`office:attach-image`·`office:attachment-preview`·`office:terminal-send`·`office:prompt`·`office:answer`·`office:answer-settings`는 `desktop/main.ts`에만 있다. `OfficeService.call`(개발 HTTP `/api/rpc`와 공유)에는 없어 웹 미리보기·Tailscale로는 도달할 수 없다. 테스트로 고정했다.
- 켜짐 여부는 main이 데스크탑 프로필 파일에서 매번 확인한다(터미널로 보내기: 파일 없음 → 기본 켜짐, 읽을 수 없음 → 꺼짐. 답하기 두 개: 파일 없음·읽을 수 없음 → 꺼짐). 공유 설정·웹 미리보기와 무관하다.
- 외부 명령은 shell 없이 `execFile`과 인수 배열, timeout·출력 한도로 실행한다. `orca`·`tmux`·`codex`는 Finder 실행의 좁은 PATH를 고려해 고정 경로 후보에서 찾는다.
- 로그·DB에 handle과 입력 내용을 남기지 않는다. 터미널에서 읽은 입력창 글은 확인 미리보기로만 렌더러에 잠깐 전해지고(저장하지 않음), 지울 때는 main이 클립보드에 넣는다. 내가 업무 카드에서 작성한 미전송 채팅은 실행별 로컬 프로필에 즉시 임시 저장하며 팝업·전체 카드가 공유한다. 성공 전송 시 같은 초안만 지우고 실패·확인 취소·터미널 글 대신 보내기는 유지한다. 서버 DB·공유 환경설정·인수인계에는 초안을 넣지 않는다.

## 쓰지 않는 방법

조사 근거는 이슈 #8 본문과 댓글에 있다.

- Claude Code 세션 간 메시지 소켓(`messagingSocketPath`, `<pid>.<hash>.key`): 문서화되지 않은 내부 프로토콜이고 토큰을 읽어 세션 간 권한 경계를 외부 앱이 우회하게 된다.
- tty 장치 쓰기(출력만 됨), TIOCSTI(macOS에서 root 필요), `claude -p --resume`(열린 세션과 대화가 갈라짐), 키 입력 흉내(포커스 탈취·손쉬운 사용 권한).
- 터미널과 무관한 실행 래퍼(pty 직접 소유)는 미검증 후보다.

## 알려진 한계

- 입력창 글 전체를 알 수 없으면(tmux에서 입력창이 최대 줄 수에 닿음, Orca에서 2줄을 넘을 수 있는 글, 예전 Orca) 여기서 지우지 않는다. Orca는 추천 글과 초안을 구분하지 못해 추천 글이 떠 있어도 한 번 확인을 거치고, 추천 글만 떠 있는 입력창은 여기서 비우지 못한다. 최대 줄 수 공식은 2.1.296 측정값이라 Claude Code가 바뀌면 다시 재야 한다.
- Orca 경로는 상태 확인과 제출 사이를 Orca가 처리하므로, 그 짧은 사이에 턴이 시작되는 경우는 막지 못한다. tmux는 Enter 직전에 다시 확인한다.
- 셸 없이 tmux 패널의 첫 프로세스로 `claude`를 띄우면 Ctrl+Z가 실제로 멈추지 못한다(작업 제어 없음). Claude 화면만 일시정지 안내가 되고 입력은 셸 없이 tty에 찍힐 뿐 실행되지 않는다.
- 첫 조회는 전체 프로세스 표와 Orca CLI 때문에 기기 부하에 따라 1~2초 걸린다. 이후에는 Orca 약 0.5초, tmux 수십 ms. Codex 조회는 수 ms다.
- Codex 화면 제목에 현재 대화 ID(전체 또는 유일하게 복원되는 32자 축약형)가 없으면 이동할 수 없다. 아래 설정 후의 화면만 지원한다. 대화가 여러 화면에 열려 있으면 임의 선택하지 않고 재개 명령을 복사한다.
- Codex가 맡고 있지 않은 세션(화면을 닫은 지 오래됨 등)에는 보내지 않는다. 그 세션을 Codex에서 다시 열면 다시 대상이 된다.

## 여러 Office 베타의 원격 채팅

독립 command API가 원격 컴퓨터의 기존 전송 어댑터를 호출한다. 조회 token과 별도 sendToken/allowSend, 양쪽 앱의 기존 전송 설정, 공유 프로젝트 범위, fresh 대상 검사를 통과해야 한다. 원격은 draft 덮어쓰기·질문 답변·재개·터미널 이동을 제공하지 않는다. 요청 중복/미확인 처리와 운영 절차는 [여러 Office 베타](MULTI-OFFICE.md)의 원격 채팅 계약을 따른다.

## Codex Desktop 대화 전송

일반 앱의 `desktop/codex-send.ts`가 rollout의 originator로 CLI 대기열과 Desktop
연결을 구분한다. 베타 플래그나 저장소 migration 없이 기존 `office:terminals`와
`office:send`를 사용한다. LAN 베타 exporter도 이 공통 모듈을 사용하고, 원격
인증·중복 방지는 베타 API 계층이 담당한다.

- `Codex Desktop` originator인 사용자 대화만 같은 사용자의
  `$CODEX_HOME/ipc/ipc.sock`에 연결한다. subagent·exec는 제외한다.
- `desktop/codex-desktop.ts`는 길이(4바이트 LE)+JSON 프레임을 사용한다.
  `initialize` v0 → `thread-owner-discovery` v1 → 해당 owner를 지정한
  `thread-follower-read-model-settings` v1로 확인한다. resumed/default/user만 허용한다.
- 전송 직전에 다시 확인한 owner에 `thread-follower-start-turn` v2를 한 번 보낸다.
  conversationId/threadId와 text input을 지정하고 `inheritThreadSettings: true`로
  모델·권한·작업 폴더 등은 Desktop의 기존 설정을 따른다. turn ID를 포함한 응답을
  받아야 성공이다. 응답 유실·프로토콜 불일치·연결 종료는 자동 재전송하지 않는다.
- Endpoint는 같은 UID, 비공개 디렉터리/소켓이어야 한다. symlink·없는 소켓·잘못된
  권한은 거절하고 파일을 생성/수정하지 않는다. 연결은 요청 후 닫는다. 들어오는
  owner discovery에는 항상 false로 답하며 방송·승인 요청을 처리하지 않는다.
- Desktop을 시작하거나 owner 없는 대화를 새 서버에서 resume하지 않는다. DB,
  인증 파일, Desktop 설정, 대화의 approval policy를 수정하지 않는다.
- UI는 `TerminalTarget.desktop`으로 Desktop 전송을 표시한다. CLI처럼 작업 종료 후
  대기열 처리를 보장하지 않는다. 실행 중 거절/응답 불명확 시 원래 대화 확인을 안내한다.

이 IPC는 2026-10-18 설치된 Desktop의 로컬 코드와 양쪽 Mac의 읽기 전용 조회에서
확인한 **비공개 호환 계약**이다. [공개 App Server API](https://learn.chatgpt.com/docs/app-server)의
공식 Desktop 연결 API로 간주하지 않는다. 앱 업데이트로 버전/메서드가 바뀌면
전송 불가로 처리하며, 다시 프로토콜을 검증해야 한다. 외부 소스 코드를 복사하지 않았다.

검증: `tests/codex-desktop.test.ts`는 실제 임시 Unix socket owner로 분할 프레임,
origin/owner 검증, 설정 상속, 잘못된 권한/프로토콜, 응답 유실 시 단일 dispatch를
확인한다. UI는 합성 카드만 사용한다. 개인 대화에 실제 테스트 메시지를 보내는
검증과는 구분한다. Playwright 수집기 홈/DB는 `.local/ui-tests`로 격리한다.

## 모바일 웹 전송

설정에서 켜는 [모바일 웹](MOBILE-WEB.md)은 Desktop main의 동일 전송 함수를 사용한다. 접속 세션·현재 공유 범위·기존 전송 설정을 확인하며, 터미널 입력과 Enter 직전에 선택적 권한 콜백으로 재확인한다. 웹에는 초안 교체·승인 자동 응답을 노출하지 않는다. 일반 Desktop IPC의 기존 동작은 이 선택적 콜백 없이 유지된다.

## 오래된 세션을 tmux로 재개 (#178)

로컬 Claude/Codex 업무 카드의 **tmux로 재개**는 저장된 provider/nativeId/cwd를 사용해 기존 대화를 이어간다. 새 대화 생성이나 자동 메시지 전송은 하지 않는다. 프로젝트 폴더·tmux 이름·재접속 안내를 먼저 표시하고, main의 네이티브 확인창에 동의해야 프로세스를 띄운다. 실행 중인 같은 대화가 있으면 먼저 작업을 마치도록 안내한다.

전용 `tmux -L agent-office` 서버에 `office-<provider>-<ID hash>` 이름을 사용한다. 처음 서버를 만들 때 사용자 tmux 설정을 읽지 않아 기본 Ctrl+B, D 안내와 종료 동작을 유지한다. 앱 재시작 후에도 이름과 소유 마커로 다시 찾으며 일반 사용자 pane에 명령을 입력하지 않는다. 살아 있는 관리 세션은 재사용하고, 소유한 단일 dead pane은 확인 후 `respawn-pane`으로 재개한다(`-k` 없음). 새 세션은 `new-session -d -x 200 -y 50`으로 만든다: 기본 80×24에서는 Claude 입력창이 7줄까지만 보여 긴 초안이 가려진다. 클라이언트가 붙으면 tmux(`window-size latest`)가 그 크기로 바꾸고, 떨어진 뒤에는 마지막 크기를 유지한다(tmux 3.6a 임시 서버로 확인). 다른 세션의 이름 충돌·조회 실패는 실행하지 않는다. 같은 앱의 시작 요청을 직렬화하고 확인 후 폴더와 tmux를 재검사한다.

실행은 `claude --resume <id>` 또는 `codex resume <id>`이며 승인 우회 옵션이나 프롬프트를 추가하지 않는다. 폴더와 실행 인수는 문자열 셸 코드로 합치지 않는다. Finder 환경에서도 사용자 `.local/bin`, Homebrew, PATH에서 실행 파일을 찾고 자식의 PATH를 보완한다. 원래 프로필 환경을 전달하며 tmux 서버의 오래된 CLAUDE_CONFIG_DIR/CODEX_HOME/CLAUDECODE가 섞이지 않게 한다.

재접속 명령 복사는 macOS/Linux에서 제공하고 macOS는 Terminal에서 열기도 제공한다. 터미널을 닫아도 tmux는 유지되지만 재부팅·프로세스 종료 후에는 다시 재개해야 한다. Windows/OpenClaw·웹/모바일·다른 오피스 세션에는 기존 대화의 재개 API를 제공하지 않는다. 네이티브 확인창 동안 `cards.dialog`로 카드 blur 숨김을 보류한다.

## 새 에이전트 소환

프로젝트 구역/깃발의 **+** → 폴더 선택(여러 원본 프로젝트가 있는 구역) → Claude/Codex와 에이전트 이름·첫 메시지(선택) → 연결과 이름 확인 → tmux에 소환하기. 채팅 카드에는 기존 대화 재개만 둔다. 바닥 깃발 아래의 +와 프로젝트 숨김은 평소 감추고, 깃발에 마우스를 올리거나 키보드로 포커스할 때 검은 버튼으로 함께 표시한다. 같은 창 맨 위의 **기존 동료 불러오기**는 이 프로젝트의 대기·보관 동료를 골라 기존 tmux 재개·Orca 새 탭 재개로 이어가고, 터미널이 열린 뒤 `returnToOffice`로 사무실에 데려온다([기능 정책](../golden/FEATURE-POLICY.md#프로젝트--기존-동료-불러오기)).

macOS/Linux에서 tmux와 선택한 CLI가 필요하다. 동일 프로젝트의 기존 Orca/tmux 연결을 보여주며 기존 세션으로 이동할 수 있다. 실제 실행 직전에 연결 상태를 다시 확인해 새 tmux를 띄울지 네이티브 확인한다. 기존 대화 재개도 같은 대화가 연결돼 있으면 확인에 표시한다.

입력한 이름(글자·숫자·공백·하이픈·밑줄, 1~40자)을 tmux 이름에 넣고 provider/짧은 구분자를 붙인다. 같은 프로젝트·종류·이름의 실행 중 세션은 재사용하며 다른 이름이면 별도 에이전트를 시작한다. 종료 후 소환은 새 대화이며 이전 대화 재개는 해당 대화 카드에서 한다.

새 대화가 수집되고 실제 CLI와 소유 tmux pane 연결이 확인되면 앱 별명으로 저장한다(최대 약 10초 + 수집 시간). 기존 수동 별명은 보존하고 한 번 적용한 이름을 반복 적용하지 않는다. 원본 provider 기록·인증 설정은 수정하지 않는다. 앱에 대화가 나타나기 전에 CLI를 종료하면 별명 연결이 되지 않을 수 있다.

**소환 세션과 대화의 연결.** 소환된 대화는 id가 생긴 뒤에도 소환 세션에서 계속 찾는다(재개 상태·Terminal 열기·재개·중복 실행 확인). 세션에 대화 표식 `@agent_office_native`(`<provider>:<대화 id>`)를 둔다. 에이전트별 차이는 `desktop/tmux-resume.ts`의 실행 어댑터가 맡는다. Claude는 새 대화 id를 미리 정해 `claude --session-id <uuid>`로 띄우고 같은 명령에서 표식을 남긴다(빈 pane을 다시 띄울 때마다 새 id). Codex는 id를 미리 정할 수 없어 표식이 비어 있다가, 위 별명 연결과 같은 검증(살아 있는 CLI → 정확한 소유 pane)이 끝나면 `adopt`가 남긴다. 이 검증은 표식이 없는 이전 소환과 Claude `/clear` 뒤의 새 대화에도 표식을 붙인다. 표식은 이름·토큰이 그 폴더·종류·이름의 소환과 정확히 맞는 전용 서버 세션에서만 인정한다. 재개 이름 세션이 있으면 그것이 먼저고, 살아 있는 세션이 끝난 세션보다 먼저다. 끝난 소환 세션의 재개는 그 세션 pane에서 `--resume`으로 다시 띄우며 소환 이름·토큰을 유지한다.

Terminal 열기(macOS) 또는 재접속 명령 복사로 직접 작업한다. Ctrl+B 다음 D로 분리하고 재접속한다. 로컬 소환은 macOS/Linux 전용이며 웹에는 제공하지 않는다. 연결된 원격 사무실은 데스크톱 앱에서 아래 별도 경로로 소환한다.

소환의 첫 메시지는 최대 4,000자이며 새 인터랙티브 CLI 시작 시 positional prompt로 전달한다. 기존 실행 재사용·재접속 시에는 전송하지 않는다. CLI가 첫 대화 기록을 쓰면 수집기가 오피스에 표시하며, 로그인/프로젝트 신뢰 대기는 터미널에서 완료해야 한다. 빈 입력은 기존처럼 터미널에서 직접 첫 메시지를 보낸다. 프롬프트는 shell 평가 없이 별도 argv로 전달하고 tmux의 끝 세미콜론 문법만 escape한다.

### 원격 프로젝트의 새 세션

연결된 사무실의 프로젝트 구역/한줄 깃발 **+**에서 Claude/Codex, tmux/Orca, 이름·첫 메시지를 선택한다. **연결과 이름 확인** 후 목적지 사무실·작업 폴더를 확인하고 **원격에서 소환하기**를 누른다. 데스크톱의 네이티브 확인창을 승인하면 해당 컴퓨터에서 새 인터랙티브 CLI를 시작한다. 현재 내 컴퓨터에 설치된 도구와 무관하며, 원격 컴퓨터의 CLI 로그인·프로젝트 신뢰 확인이 필요할 수 있다.

실행 위치는 화면에서 묶인 프로젝트의 검증된 `workspace.worktree` 루트다. 하위 폴더의 여러 대화가 한 프로젝트로 묶여도 임의 대화의 cwd를 선택하지 않는다. 작업공간 근거가 없을 때만 원본 cwd를 사용한다. 클라이언트가 임의 경로·실행 파일을 전달할 수 없다.

tmux는 원격의 전용 `agent-office` 서버에 만들고, 같은 폴더·종류·이름의 실행 중 슬롯은 재사용한다. Orca는 해당 컴퓨터의 런타임과 등록된 로컬 작업공간을 확인해 새 터미널 탭을 **포커스 이동 없이** 만든다. 원격 Orca 환경 변수로 다른 호스트에 다시 우회하지 않는다. 각 CLI의 절대경로는 원격에서 찾고, 첫 메시지의 따옴표·줄바꿈·셸 구문은 그대로 전달한다. 권한 우회 플래그는 추가하지 않는다.

첫 대화가 기존 수집기에 감지되면 원격 사무실에 표시된다. 연결 권한·공유 범위·중복 생성과 배포 설정은 [여러 Office 베타의 원격 소환](MULTI-OFFICE.md#원격-소환-계약)을 따른다.

### 일부가 가려진 Claude 입력창 교체

부분 미리보기는 `partial: true`로 표시한다. 화면에는 숨겨진 내용/첨부가 소실되고 읽은 부분만 백업될 수 있다는 경고, ‘가려진 내용도 지우고 보내기’, 터미널 이동을 함께 둔다. 사용자가 교체 버튼을 눌렀을 때만 `replaceDraft`와 `allowPartialDraft: true`를 전달한다. 일반 보내기·Enter에는 이 플래그를 넣지 않는다.

입력창이 확인 때와 같을 때 Ctrl+K/Ctrl+U로 단계적으로 비우며, 매번 읽은 내용을 누적해 백업한다. 전체 글이 다시 보이는 시점부터 기존 변경 감지 경로를 따른다. 권한창/읽기 실패/전경 프로세스 변경/백업 실패/횟수 한도에서는 중단한다. 빈 입력 또는 추천 상태를 확인한 뒤 새 글이 정확히 들어갔을 때만 Enter를 전송한다. 부분 교체 성공/실패 안내는 전체 백업을 보장하지 않는다. 원격/모바일 경로에서 이 확인을 자동 승인하지 않는다.

### Codex 원격 owner

명시적으로 연결한 원격 사무실의 Codex 대화는 로컬 Codex 앱의 원격 owner로 보낼 수 있다. 동일성/권한/중복 방지는 [MULTI-OFFICE](MULTI-OFFICE.md)의 계약을 따른다. `thread-owner-discovery` v1의 params.hostId는 선택한 `remote-control:*` 또는 `ssh:*`다. follower read-model-settings는 v2, start-turn은 v3와 최상위 hostId를 사용하며 발견한 client ID에만 보낸다. 로컬 요청은 기존 v1/v2 및 host envelope 없음으로 유지한다. 설정 상속과 단일 dispatch를 유지하고 owner 부재·지원하지 않는 대화·불명확한 응답은 재전송하지 않는다.

검증: `node --import tsx scripts/codex-remote-smoke.ts`는 독립 프로필, 실제 HTTPS exporter, 합성 Codex IPC owner로 설정 UI → 원격 카드 → 전송과 권한 회수를 검사한다. 사용자 대화나 설치된 앱의 데이터를 사용하지 않는다.

## 미니 터미널 (tmux로 유지, 2026-10-26)

업무 카드·프로젝트 구역에서 그 폴더의 작은 셸을 옆에 뜨는 별도 터미널 창(폴더 셸마다 하나)으로 연다. 정책은 [기능 정책서](../golden/FEATURE-POLICY.md#미니-터미널-tmux로-유지). 데스크톱 macOS/Linux 전용(preload가 `office.shell`을 그때만 노출), 웹·모바일·데모·원격 동료·Windows에는 없다.

### 구조

| 층 | 파일 | 하는 일 |
| --- | --- | --- |
| 공통 규칙(순수) | `src/shared/mini-shell.ts` | IPC 명령 파싱(`parseShellCommand`), 입력 검증, 크기 범위, 구역의 로컬 폴더 고르기 |
| main | `desktop/mini-shell.ts` (`MiniShells`) | 전용 tmux 서버의 셸 만들기·목록·종료, `node-pty`로 `tmux attach` 클라이언트 붙이기, 창별 소유 |
| main IPC | `desktop/main.ts` `setupMiniShell` | `office:shell`(invoke) · `office:shell-input`(send) · `office:shell-data`/`office:shell-exit`(→창) · `office:shell-window`(창 열기·닫기·포커스·대상) |
| 터미널 창 | `desktop/shell-windows.ts` (`ShellWindows`) · `src/shared/shell-window.ts` | 폴더 셸마다 BrowserWindow 하나(`#shell`), 연 창 옆 자리 계산(`shellWindowBounds`), 크기 기억, 최대 6개 |
| 화면 | `src/components/MiniShell.tsx` · `ShellWindow.tsx` · `MiniShellPanel.tsx` · `src/lib/miniShell.ts` | 버튼(창 열기 요청), 터미널 창 화면, xterm.js 그리기(지연 로드 청크) |

- **tmux**: `tmux -L agent-office-shell -f /dev/null new-session -d -x <cols> -y <rows> -s shell-<sha256("shell:"+폴더) 앞 16자> -c <폴더> <로그인 셸> -l` 뒤에 같은 명령 큐로 `@agent_office_shell_cwd`(base64 폴더)·`@agent_office_shell`(전체 토큰)·`status off`·`mouse on`을 건다. 셸은 tmux가 exec하며(셸 문자열 아님) 로그인 셸은 `/etc/shells`에 있는 것만 쓴다. 목록은 이름·토큰·폴더가 서로 맞는 세션만 인정한다. tmux 재개의 `agent-office` 서버와 사용자의 기본 서버는 건드리지 않는다. 테스트는 `AGENT_OFFICE_SHELL_SERVER`로 버릴 서버를 쓴다(`agent-office`는 거부).
- **PTY**: `node-pty`로 `tmux -u -L agent-office-shell attach-session -t =<이름>`을 띄운다. 창(webContents id)마다 `ptyId`(UUID)를 주고, 쓰기·크기 변경·분리는 그 창의 `ptyId`일 때만 따른다. 출력은 8ms씩 모아 한 메시지로 보낸다. 창이 닫히거나 다시 로드되면(`destroyed`/`did-start-loading`) 그 창의 클라이언트만 끝낸다. 앱 종료도 클라이언트만 끝낸다 — 셸은 tmux에 남는다.
- **환경**: 자식은 `TMUX`·`TMUX_PANE`·`CLAUDECODE`를 지우고 `TERM=xterm-256color`, 로캘이 없으면(Finder 실행) `LANG=en_US.UTF-8`.
- **입력 제한**: 한 번에 64KB 이하 문자열. 더 큰 붙여넣기는 창이 32KB씩 나눠 보낸다. 크기는 10–400열, 3–150행으로 자른다. 그 외 모양의 명령은 `badRequest`.
- **출력 흐름 제어**: 창은 xterm에 넘겼지만 아직 그리지 않은 양을 센다(`OutputFlow`). 256KB를 넘으면 `flow` 명령으로 main이 그 창의 PTY 읽기를 멈추고(`pause`), 32KB 아래로 내려오면 다시 읽는다. 다른 창의 PTY는 건드리지 못한다.
- **종료 확인은 그 셸에만**: 확인 창을 띄우기 전 tmux `#{session_id}`·`#{session_created}`를 적어 두고, 동의 뒤 다시 읽어 같을 때만 `kill-session -t <$id>`로 끝낸다. 그 사이 다른 창이 끝내고 같은 폴더로 다시 띄운 셸은 끝내지 않는다.
- **터미널 창**: 버튼은 `office:shell-window`의 `open`으로 `{id}`(세션) 또는 `{name}`(기존 셸)만 보낸다. main은 세션의 폴더를 수집기에서 읽어(`describeShell`) 창 키(셸 이름)를 정하고, 그 키의 창이 있으면 앞으로 가져오고 없으면 보낸 창(`BrowserWindow.fromWebContents`) 옆에 만든다. 창은 로드 뒤 `target`으로 자기가 보여 줄 대상을 묻고, 그다음은 예전과 같은 `office:shell` `open`/`attach`다. 창을 닫으면 webContents가 사라져 그 창의 클라이언트만 끝난다(`detachOwner`). 터미널 창은 `trustedShell`(미니 터미널 IPC)에서만 신뢰하고 snapshot은 받지 않는다. 테두리 없음, `-webkit-app-region: drag` 머리줄로 옮기고, 카드·책상 줄에서 열면 카드와 같은 `pop-up-menu` 층·모든 Space에 뜬다. 조용한 실행에서는 `showInactive`만 한다. 미리보기 카드는 포커스가 터미널 창으로 가면 닫히지 않고(`companion`), 터미널 창이 포커스를 잃으면 다시 확인한다(`recheck`). 창 만들기·자리·크기 기억·뜨기·조용한 실행·창별 신뢰는 북마크 읽기 창과 같은 공통 틀(`desktop/popup-windows.ts`, [팝업 카드](POPUP-CARDS.md) · 옆에 뜨는 팝업 창)이고, `ShellWindows`는 종류 설정만 가진다.
- **Ctrl 키**: Windows/Linux의 업무 카드 창·터미널 창도 큰 창처럼 앱 메뉴(Edit)를 떼어(`dropAppMenu`) Ctrl+C·Ctrl+A가 메뉴 대신 셸로 간다. macOS는 그대로.
- **화면 숨기기**: 켜진 snapshot이 오면 main이 터미널 창을 모두 닫아(분리) 내용이 남지 않게 하고, 켜져 있는 동안 `open`을 거부한다. 버튼도 막는다. 큰 사무실이 데모로 바뀌면 `close-all`(큰 창만 허용)로 모두 닫는다.
- 터미널 창 안의 keydown은 위로 올리지 않는다: Esc·글자 단축키가 카드·사무실이 아니라 셸로 간다. 스크롤은 tmux `mouse on`(휠 → copy-mode), 선택은 Option+드래그.

### node-pty와 패키징

- `node-pty@1.1.0`(정확히 고정, `optionalDependencies`): N-API 프리빌드(`prebuilds/darwin-{arm64,x64}`)라 Electron 버전마다 다시 빌드하지 않는다. 빌드 도구가 없는 곳(리눅스 CI 등)에서 컴파일이 실패해도 설치는 계속되고, main은 처음 쓸 때 `import('node-pty')`하므로 앱은 뜨고 미니 터미널만 '터미널을 붙이지 못했어요'가 된다.
- 1.1.0은 macOS `spawn-helper`를 실행 권한 없이 배포해 모든 spawn이 `posix_spawnp failed`로 실패한다. `postinstall`(`scripts/node-pty-helper.mjs`)과 패키징에서 0755로 고친다.
- esbuild 번들에서 `node-pty`는 external. `scripts/package.mjs`가 `lib/`(테스트·맵 제외)·해당 아키텍처 프리빌드·LICENSE만 `node_modules/node-pty`로 넣고, `asar.unpack: **/node_modules/node-pty/prebuilds/**`로 `pty.node`와 `spawn-helper`를 `app.asar.unpacked`에 둔다(node-pty가 경로의 `app.asar`를 `app.asar.unpacked`로 바꿔 찾는다). codesign이 둘 다 서명한다. Windows 패키지(`package-win.mjs`)에는 넣지 않는다.

## 전송 확인의 연속성

성공한 전송은 원본 transcript에 대응될 때까지 대화에 로컬 확인으로 남는다. 카드/앱 재시작과 여러 창을 지원하며 동일 원본 요청 하나가 반복 전송 두 개를 지우지 않는다. 저장하는 것은 식별자·시각·이미지 장수와 SHA-256 지문이며, 요청 본문이나 첨부 파일 경로를 추가로 보관하지 않는다. 다른 창/재시작 뒤에는 본문 없는 전송 확인을 보여 준다. 확인 표시는 30분 유효/50건 한도이며 다음 조회·시작 때 만료 정리한다. 숨기기는 확인 표시만 지우며, 실제 에이전트 전송 취소나 재전송을 뜻하지 않는다. WebCrypto가 없는 환경에서는 재시작 후 원본 대응을 추측하지 않는다.

Codex Desktop이 이미지 단독 입력을 transcript에 기록하지 않는 경우에는 해당 제한과 첨부 장수를 표시한다. 전송 확인 저장 실패로 이미 성공한 전송을 다시 보내지 않는다. 원격의 `sent`/`uncertain` 전송 장부는 별도 서버 정책을 유지한다.
