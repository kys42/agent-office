# 팝업 카드 위치와 독립 창 (#157)

팝업 헤더는 위치 기억 · 이 카드 고정 · 큰 사무실 · 더보기 · 닫기 순서다. 팝업의 인수인계 꾸리기는 제거했고, 사무실에 동료를 남기는 기존 핀은 더보기로 이동했다. 큰 사무실의 인수인계와 동료 핀은 유지한다.

## 서로 다른 두 동작

- **위치 기억**: 현재 좌표를 일반 팝업의 기본 위치로 저장한다. 일반 팝업을 다시 드래그하면 새 위치를 저장한다. 해제하면 클릭한 책상 근처에 열린다. 기본 크기는 기존 `card-size.json`, 위치는 로컬 `card-position.json`에 저장한다. 위치 저장 실패는 상태를 바꾸지 않고 알린다. 모니터가 제거되거나 작업 영역이 바뀌면 현재 영역 안으로 보정한다.
- **이 카드 고정**: 지금 보여 주는 대화의 창을 독립 창으로 남긴다. 다른 동료를 열어도 창의 내용·위치·작성 중인 글을 교체하지 않는다. 같은 대화를 다시 열면 기존 고정 창으로 이동하며, 같은 보기면 Inspector를 재마운트하지 않는다. 각 창을 드래그·크기 조절하고 Esc·닫기로 닫을 수 있다. 고정 창에서 터미널/큰 사무실로 이동해도 카드를 남긴다.
- 고정 창의 위치와 크기를 바꿔도 일반 팝업의 위치·크기를 덮어쓰지 않는다. 고정 창의 위치 기억 버튼을 명시적으로 누르면 그 위치를 일반 팝업의 기본 위치로 지정한다. 고정 창과 새 팝업이 겹치면 기존 창을 움직이지 않고 새 팝업만 40px씩 비켜 열어 헤더를 남긴다.
- 고정을 해제하면 그 카드를 일반 팝업으로 돌리고 기존 일반 팝업은 정리한다. 다른 고정 창은 유지한다. 미전송 글은 기존 실행별 로컬 초안 저장 계약을 따른다.
- 재실행 때 위치·기본 크기는 복원하지만 고정 카드를 자동으로 다시 열지는 않는다. 이전 `office:card-keep`은 바깥 클릭 닫기만 막던 전역 상태여서 독립 창으로 자동 승격하지 않는다.

## 창 수명과 IPC

`desktop/card-windows.ts`가 일반 팝업 하나와 고정 창들을 관리한다. 카드마다 target, blur 타이머, 드래그, 크기, 네이티브 확인창 수를 따로 가진다. 닫힌 일반 팝업은 재사용하고 고정 창은 닫을 때 파괴하여 snapshot 구독·타이머를 정리한다. 모든 카드는 기존 수집기와 `SnapshotDelivery`를 공유한다.

카드 제어와 상태 조회는 해당 카드의 main-frame sender에만 허용한다. `office:card-state` 초기 조회가 렌더러 구독 전에 보낸 target도 복원한다. 상태 이벤트는 해당 창의 대상·카드 고정·위치 기억만 전달한다. 네이티브 확인창이 열려 있는 동안에는 그 카드의 blur 닫기만 보류한다. 기본 위치는 macOS panel 활성화 뒤 다시 적용해 숨긴 창의 자동 재배치가 저장 위치를 덮지 않게 한다.

## 검증

- `tests/card-windows.test.ts`: 잘못된 위치, 책상 기준 배치, 저장 위치, 모니터 제거·작은 작업 영역, 고정 창 헤더를 남기는 배치.
- `tests/ui/card.spec.ts`: 새 헤더/메뉴, 두 토글의 독립성, 오류 시 상태 유지, 초기 target 복원, 드래그·키보드·입력·개인정보.
- `npm run test:cards`: 개인 데이터와 분리한 실제 Electron에서 여러 고정 창·재사용·blur·닫기·고정 해제·독립 초안·IPC sender·재실행 위치 복원·위치 기억 해제를 검사한다. `test:package`도 DMG에서 복사한 앱으로 같은 검사를 실행한다.
